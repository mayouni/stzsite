## The grammar {#grammar}

Six efforts in two years, for six different readers, have converged on one grammar. None of them shares code with another, which is the argument for a foundation.

<ol class="steps">
<li value="1"><b>A window with three permanent regions.</b> A spine that lists the facets, a workspace where the work is, and a context rail. A title bar sits above and a status bar below.</li>
<li value="2"><b>An identity bar.</b> The project or session, the user, the theme, the language, a mode from guided to expert, and one primary action.</li>
<li value="3"><b>A ribbon ordered by a solution's lifecycle</b>, not by the tool's features: for example Design, Data, Build, Intelligence, Operate, Support; or Define, Architect, Build, Govern, Ship.</li>
<li value="4"><b>An explorer over closed-grammar files</b>, each kind with its own extension.</li>
<li value="5"><b>A context rail that proposes and never commits.</b> It changes with what is focused, and its assistant panel shows its context and the rule that governs it everywhere: a proposal is reviewed like a human's.</li>
<li value="6"><b>A status bar that tells the truth</b>, and governance in every cell: proposals as counts, a violation as a badge, cost against budget, and in guided mode every change previewed before it lands and reversible after.</li>
</ol>

What makes it Softanza's and not another shell: the ribbon follows the solution's lifecycle, the rail proposes with a court beneath it, and governance is a first-class cell.

## Two shells, one chrome {#shells}

Which shell should an environment have? The ruling is both: the page in your browser and the window on your desktop, declared once, and proved to agree.

<div class="cards">
<div class="card"><h3>The page in the browser</h3><p>One file to run, no install on any machine with a browser, the same page that an agent, a remote reviewer or a phone opens. Its costs, as written: a browser tab and not a native window, the browser's file-access model, and a local port that must be treated as a surface. Measured for a sound studio, not yet for an environment.</p></div>
<div class="card"><h3>The window on the desktop</h3><p>A single executable with no runtime and no framework, input to screen under sixteen milliseconds, no port, the host's own dialogs, the graphics card for a large code graph. Its costs: a native widget layer to build or project, and a latency constraint owed as a measurement, not a promise.</p></div>
</div>

Three constraints carry both. One declaration: no chrome element exists in one shell and not the other. Agreement proved: the guard that checks a picture rendered by two backends is extended to the chrome. Latency measured, not inherited: each shell carries its own number, dated, with its method, a loss published where it stands.

<p class="way"><span>The Softanza way</span> A picture is described once and rendered twice, so the two backends cannot disagree about where anything sits. For pictures that sentence is checked by a guard with twenty-four assertions, written because until it existed, "cannot disagree" was an argument and not a result.</p>

<p class="proof"><b>designed</b> No environment of this family ships today. One shell ships, for the sound plane. The foundation that would make the next one a projection of a declaration, a shell kit, a declared chrome, the facet as data, the rail and the governance cells as library verbs, is specified and not built. The two shells' latency was not measured, and whether the current panel kinds reach a native window without new plumbing was not tested.</p>
