## Decisions taken here, each with the fact behind it

- **Diko stays unnamed on the site** until the author says otherwise: the project memory records "never name a customer without consent; DIKO is internal". It is told as "a knowledge hub for a public institution", with its lesson, and named the day consent is given.
- **Zui stays.** It names a law of Softanza (122 rules, 22 verbs), listed in the estate beside Haro and Harobanda; the word the author refused is Zin, and it is gone. (An earlier version of this plan renamed the page; the sources show no Zin on it, so there is nothing to rename.)
- **Teaching and Pedagogy merge into one flow** under Learn: a page "Teach" with three doors (I learn by myself; I teach; I run a programme or an institution) and, first, the proposition. The reconciliation with Zin leaves the site; the charter that holds it stays linked from the library.
- **Examples show the natural name and say how it ran**: `? o1.IsChar()` with, under the row, "written IsAChar() in the library today: the host language holds the word; Haro removes the detour". The run line states the spelling that ran. The site already presents the Haro face for prose; this is the same stance for a known, listed set of names, never for anything else.
- **An alias folds into its root, the root being the method with the body**: `Value` lists under `Content` as "also written Value()"; `HasMoreChars(3)` and `HasMoreChars(:Then = 3)` under `HasMoreCharsThen`. The root is where the code is; the author's example agrees.

## The waves

### Wave 1 -- mechanical, DONE 2026-10-03 (e8c6db28 + the next commit)

Measured after: 19,992 external links on 4,083 pages open in a new tab, 19,992 carry the mark (the arrow is drawn in the link's own colour; a link that wraps a card or an icon gets the tab and no arrow); the extension paragraph is one line on 618 class pages (each letter of a strip carries its meaning as a title); a pinned path `Learn > Reference > String > stzString > Find()` stands on every page deeper than its section (class, entry, A to Z, guide, how-to, narration, book proof, atlas group); 6,836 of the 6,852 composed examples whose answer is not a list are written with `?` alone and were run again in that form, the 1,993 that print a list keep `@@()`; "Zin" is gone from the markdown, the data, the diagrams (four regenerated) and the built pages, and the build refuses it from now on; 0 failures on 34,356 example blocks, 0 dangling among 560,619 local links. The page the author proposed to measure at 390 px keeps four pinned rows (menu, section, path, classes); the path row scrolls sideways there.

The five items, as planned:

1. **External links** (obs. 1): every `href` that leaves the site gets `target="_blank" rel="noopener"` and a small "external" mark after the text (an arrow glyph in the link's colour, never an image), in `tools/build.py` on every page; the proofs and the agents' files untouched.
2. **The extension reminder** (obs. 9): the paragraph leaves the class and entry pages; one short line stays above the table ("bold and ticked: the extension exists · struck: it does not · what they mean"), the letters of the strip carry their meaning as a title, and the catalogue stays on the reference index.
3. **The path** (obs. 11): a pinned path line on every page below the main menu, `Learn > Reference > String > stzString > Find`, each step a link; the left bar keeps the siblings. The site's navigation law already asked for it ("menu + section path pinned").
4. **`@@()` only for lists** (obs. 6): `tools/rows_run.py` runs the plain `? call` form in its verification pass for every example whose output is not a list, keeps the plain form when it prints the same value, and the data is regenerated; the catalogue's 19 extension examples and the narrations' own code are not rewritten (they are the library's). About 50 minutes of machine.
5. **Zin leaves the site** (obs. 5, first half): the 166 mentions are rewritten as Softanza's own design (what was done, not where it came from), the Zui page is renamed, `tools/check_examples.py` gains a rule that the word does not come back.

### Wave 2 -- one name per thing, in the reference and everywhere (obs. 2, 7, 8)

6. **`tools/aliases.py`**: reads the library sources once and emits `data/names.json`: for each class, `alias_of` (an empty subclass of another); for each method, `alias_of` (a definition that forwards unchanged), the named-parameter forms it accepts (read from the `IsXNamedParam` tests in its first lines), and `detour` (from a short hand-kept list `data/detours.json`, reviewed with the author: IsAChar, IsAString, IsANumber, IsAList, IsAnObject...). Like `tools/qforms.py` for the extensions, it is a catalogue the build folds by.
7. **The fold**: a class under its alternative names has one page, titled by its root and saying "also named stz2DList, stzLists"; the old addresses redirect; the class index, the A to Z, the guides, the atlas and `agents/index.json` (`also_named`) follow. A method lists once, under its root, with "also written: Value() · HasMoreChars(3) · HasMoreChars(:Then = 3)", an example on the root only, the extensions strip unchanged. Functions are folded the same way where the site lists them (the Ask page, the recipes).
8. **A "Names" section in the documentation design and on the reference index**, beside the extensions: a method has one root name; alternatives exist so a sentence reads naturally; an extension adds a word; a detour is a spelling the host imposed. Four kinds, each explained once.
9. **The agents' index and llms.txt** state the rule in one sentence, so an agent asks for the root.

The measure after: the reference lists 18,229 roots (today 22,272 rows), 572 classes (today 618), 0 alias pages, every alternative reachable by search and by its old address.

### Wave 3 -- search (obs. 10)

10. **One index, built at build time**: `data/search-index.json` (areas > classes > methods, with each method's one-line description, its root and its aliases, its example's code) split in two files: names first (about 400 KB, loaded when the field gets focus), descriptions and code on demand.
11. **One field, everywhere under Learn**: results as the reader types, grouped area > class > method, the match highlighted in the name, the description or the code line; the keyboard walks them; Enter opens; what matched is said ("in an example", "in the description"). On a class page the same field searches the page first and the library next, in two groups. Measured against ten questions a reader asks ("remove duplicates", "FindW", "banana split", "sort a hash list by value"), each answered in the first five results, before it ships.

### Wave 4 -- learning, teaching and pedagogic design as one flow (obs. 4, 5 second half)

12. **The proposition page first**, "Softanza for education", what no framework and no e-learning provider offers, each claim proven on the page: the course is code that proves itself (15 chapters, 4 languages, 149 promises run); a lesson is a cell, and a cell links to its proof; the tutor is a program of the library (`stzTutor`), not a person and not a language model, with three rules it cannot break; a level is earned by a project whose guard passes, never by an exam; an institution lays an overlay and the course reasons about its world without a fork; progress is a text file the learner owns and a pass is the fingerprint of the work; a cohort's report is a narration; the course reads in English, French, Arabic and Hausa.
13. **Three doors on the Learn page**: *I learn by myself* (the book, the ladder, the reader), *I teach* (exercises, the tutor run for a learner, the cohort, the skills and stages, the recap cell, the missions), *I run a programme* (the overlay, the court that refuses a fork, the four editions, the evidence an institution keeps). The teacher's door names what a teacher does, in order, with the class and the command for each step, run.
14. **Teaching and Pedagogy become that one flow**: the pedagogic engineering (skills, stages, profiles, the recap cell, progressive revelation) is presented as Softanza's design, under "I teach" and "I run a programme"; what is still missing stays said plainly (Zarma, the native reviews, the browser runtime).

### Wave 5 -- forged in projects (obs. 3)

15. **A page "Forged in projects"** under Platform (and a short chapter in History): one section per project, in the order they happened, each with three things the repositories attest: what the project needed, what Softanza learned from it, which part of the library carries the lesson, with the file. RestoLean (Lyon, 2024-2026): deployment sites, emulation of the whole solution, service virtualization, the perf system and the request bracket, the security narrations, two gestures per task. Organizium (Niamey): the web layer, the organisational model, the audit module. The customs school (Tunisia): four requirements, an assessment tool that became an organisational platform. The knowledge hub (unnamed): the document chain, the platform-of-platforms reading. The learning programme for West African learners: the learning system and the interface constitution. Dates from the repositories, quotes from their own documents, no claim without a file.

### Whenever the documentation session reports

The stzlib documentation session (`STZLIB-DOCREFORM-01`) will export a richer record of every method. Its record should carry the alias root, the accepted forms and the detour, so the site reads them instead of deriving them: asked today in CONCLUSIONS, before wave 2 starts, so the two do not diverge. If its export arrives first, wave 2 folds by that record; if not, `tools/aliases.py` stands until it does.
