Web et serveur d'applications

Le serveur est un hôte, pas une bibliothèque appelée à chaque requête : le moteur est déjà chargé et prêt, et le serveur ne fait qu'y amener les requêtes et en rapporter les résultats.

Les fonctions, par ce qu'elles font

Tester et vérifier

  • IsRunning server lifecycle dans stzAppServer
  • IsObserved routing interface dans stzAppServer
  • IsHostingAgents agents: the agent host is the same host dans stzAppServer
  • IsLive remote mode: a backend in another host dans stzAppBackend
  • IsRemote remote mode: a backend in another host dans stzAppBackend
  • IsSigned remote mode: a backend in another host dans stzAppBackend
  • IsGoverned governance + cross-part audit dans stzAppBackend
  • IsReachable Is the far backend actually answering? (stzAppServer serves /health with no route declared, so this needs nothing from the model.) dans stzAppBackend
  • IsSandbox a double declares itself -- see stzServiceRegistry dans stzPaymentsSandbox
  • IsEphemeral a directory survives a restart dans stzFileBlobStore
  • IsLocalReal a genuine local equivalent, not a fake -- see stzServiceRegistry's postures dans stzFileBlobStore
  • HasRoute Exact-only presence check (kept for back-compat / introspection). dans stzAppRouter

Trouver

  • LastMs The duration of the last crossing (ms, monotonic clock) -- the marshalling cost of one Create/Rows/RowCount, either mode. dans stzAppBackend
  • LastStatus The HTTP status of the last crossing, either mode (0 = it never completed). 401 here means the far side refused the signature. dans stzAppBackend
  • LastRoundtripMs governance + cross-part audit dans stzAppBackend

Compter et mesurer

  • NumberOfAgents agents: the agent host is the same host dans stzAppServer
  • MeanCrossingMs Mean crossing cost over the whole ledger (refusals, at 0 ms, excluded -- they never crossed). dans stzAppBackend
  • NumberOfCallsTo how many times a URL was asked for -- the assertion that catches an N+1 or a retry storm. dans stzHttpSandbox
  • NumberOfCalls COST: the fee-free promise, made measurable dans stzLlmSandbox
  • Size listing, the S3 idiom dans stzFileBlobStore

Remplacer et modifier

  • SetAgentSlice How long a single serve slice may park on the socket before due agents are ticked. Smaller = crisper agent timing, more loop turns. dans stzAppServer
  • SetSecureCookies Add Secure to the auth cookies -- TRUE whenever the listener is TLS, so the session cookie never travels in clear text. dans stzAppServer
  • SetPhase the phase -------------------------------------------------------- :development / :emulated -> sandboxes are expected. :production -> they are a violation. The phase is the SAME switch stzDelivery already uses, so nothing new decides what is real. dans stzServiceRegistry
  • SetActor Bind the acting actor: cross-part WRITES then require an effectful one (an LLMActor reads the whole solution and commits none of it). Reads are sensing and stay open. Unbound = ungoverned (dev). dans stzAppBackend
  • SetMaxSkew remote mode: a backend in another host dans stzAppBackend
  • SetSigningKey The shared secret that authenticates the crossing. Set it on BOTH sides: the HOST uses it to require a signature, the CLIENT to produce one. It is the same secret, so this one call serves both roles -- which is also why a real deployment must deliver it out of band (env, vault, stzSecretStore), never in the model file or the command line. dans stzAppBackend
  • SetStrict strictness dans stzHttpSandbox
  • SetFallback A catch-all answer, for pipelines where the text does not matter and only the SHAPE does. Setting one turns strictness off for unmatched prompts. dans stzLlmSandbox
  • SetParams Route path params (bound by the router: /user/:id -> Param("id")). dans stzAppRequest

Retirer

  • Delete routing interface dans stzAppServer
  • Remove S3's DELETE is idempotent: removing what is not there SUCCEEDS. Kept, because a test that asserts otherwise would be asserting a fiction. dans stzFileBlobStore

Convertir

  • ParseHttpRequest Parse one complete HTTP/1.1 request (the engine frames it: full headers + Content-Length body, CRLF line endings). dans stzAppServer
  • AsRuleGraph NOTE this does NOT duplicate the invariants above. Findings from Findings() already carry the report's shape, so the registry joins the shared CI gate directly: oReport.IngestLegacy(oReg.Findings(), "services"). What the GRAPH adds is the question a flag check cannot ask -- which PART of a solution depends on a fake -- and that needs the delivery's parts joined to these nodes (see stzDelivery.AsRuleGraph and stzServiceRuleSet). dans stzServiceRegistry

Afficher, dessiner et mettre en forme

  • Show governance + cross-part audit dans stzAppBackend

Lire et écrire

  • SaveModelTo Cells carry their TYPE (n/s) rather than being sniffed on the way back in: a price must stay a NUMBER for the revenue maths, and "looks numeric" is exactly how "007" silently becomes 7 -- a defect this library already paid for once in the CSV reader. Fields are percent-escaped . dans stzAppBackend
  • Save the PORT contract ------------------------------------------------ Overwrites silently when the key exists, exactly as S3 does. dans stzFileBlobStore
  • SaveFile large payloads, without passing through RAM dans stzFileBlobStore

Parcourir et appliquer

  • Run Serve forever (until the process is killed or Stop() is called from a handler). The documented blocking entry point. dans stzAppServer
  • RunFor With agents hosted, the serve slice is BOUNDED: ServeOne(nLeft) would otherwise park on the socket for the whole remaining time whenever no request arrives, and the agents -- which live on this same loop -- would never tick. So we serve for at most @nAgentSliceMs, then tick whatever is due, and repeat. Requests and perceive-decide-act interleave on ONE loop. dans stzAppServer
