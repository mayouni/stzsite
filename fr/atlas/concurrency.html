Concurrence et distribution

D'excellents substrats : nœuds, supervision, multicœur, flotte ; le vocabulaire unificateur n'existe qu'en conception.

6 Strong · 4 Solid · 1 Partial · 1 Emerging

Mesuré contre : Go · Akka · Erlang/OTP · Ray · Dossiers : base/concurrent(s'ouvre dans un nouvel onglet) · base/cluster(s'ouvre dans un nouvel onglet) · base/network(s'ouvre dans un nouvel onglet) · Le guide des fonctions de ce domaine

Repensé depuis les premiers principes

Ce que Softanza a gardé de ce qui marche, et ce qu'elle a repensé, tel que la bibliothèque l'a écrit dans ses documents de conception et ses narrations.

La manière SoftanzaLe processus est l'unité naturelle de la concurrence : les nœuds ne partagent rien, ne communiquent que par messages, et chaque passage a un coût mesuré qui décide s'il vaut la peine.

Gardé des meilleures pratiques

  • D'Erlang, Softanza reprend les processus sans partage, les messages comme seul contact, la transparence de l'emplacement et des superviseurs qui relancent les nœuds selon des stratégies déclarées. source(s'ouvre dans un nouvel onglet)
  • La boucle d'événements est libuv, intégrée et compilée depuis les sources, plutôt qu'un réacteur maison : ne pas réinventer la roue, et profiter de son support Windows éprouvé. source(s'ouvre dans un nouvel onglet)
  • La sécurité réutilise l'existant : le même signataire HMAC et le même canal TLS mutuel que le reste de la bibliothèque. Aucune cryptographie nouvelle, aucun second signataire. source(s'ouvre dans un nouvel onglet)

Repensé

  • La partie difficile est refusée par écrit : ni livraison exactement-une-fois, ni consensus, ni courtier. « Au plus une fois » est le défaut honnête ; l'état partagé va dans une base de données. source(s'ouvre dans un nouvel onglet)
  • Aucune attente n'est infinie, aucune file n'est muette. Chaque requête porte un délai obligatoire, et chaque boîte aux lettres est bornée et compte ce qu'elle rejette. source(s'ouvre dans un nouvel onglet)
  • Une topologie est une donnée qui se décrit et se recrée à l'identique. Déplacer un nœud sur une autre machine tient en une ligne : Deploy. source(s'ouvre dans un nouvel onglet)
  • La concurrence est un vocabulaire d'aiguillage, pas une machine : Concurrently envoie le travail au moteur, à la boucle ou aux processus, et ne répartit que si la mesure le justifie. (prévu) source(s'ouvre dans un nouvel onglet)

An unusual shape: the substrates are complete and excellent, while the vocabulary over them is design-only. Three sub-planes ship, each heavily guarded with real multi-process tests -- OTP-style supervised nodes, a measured-gated multicore tier, an elastic HTTP worker fleet -- over a full libuv reactor with mTLS. What is not built is the plane's own headline: the one routing vocabulary (Concurrently()) that would let you say 'do this concurrently' and land it on the right substrate.

Ce qu'un artisan en fait, et ce qui se distingue

  • OTP-style supervision proven under real kills -- the pragmatic 80% of Erlang in a non-BEAM language
  • A measured-gated multicore tier: bit-identical or justified, elementwise killed by the memory wall
  • A full libuv reactor where no callback crosses into Haro (submit -> ticket -> await)
  • An elastic HTTP worker fleet with a smart router and autoscaling, guarded with a real 3-process fleet

Ce qui est dû

  • The routing vocabulary: Concurrently() + stzTask/ticket/stzWorkshop (CN0-CN5)
  • Channels and structured concurrency
  • Federation over the node plane; UDP and a native WebSocket; a managed-PKI mTLS story
  • Dynamic task-graph distribution and live multi-machine verification

Les fonctions, par ce qu'elles font

Tester et vérifier

  • CanAdmit admission (the load-isolation primitive) dans stzWorkerProfile
  • Has queries dans stzFacetCatalog
  • IsConnected No global init required for the engine HTTP client. dans stzNetwork

Trouver

  • LastTraceId The trace id assigned to the most recent Route (correlates the front host's record with the worker's _trace on the wire). dans stzAppCluster
  • LastCallMs Duration of the last FederatedCall, ms (gates + signing + transport; refusals cost what the gates cost). dans stzComputeFederation
  • LastSignature The envelope [ :kid, :ts, :nonce, :sig ] of the most recent SIGNED FederatedCall (empty [] if the last call was unsigned). dans stzComputeFederation

Compter et mesurer

  • NumberOfTraces trace lookups dans stzClusterTelemetry

Remplacer et modifier

  • SetRateLimit Rate limit a facet at the front door: nRatePerSec sustained with a bucket of nBurst (the largest instantaneous burst absorbed). A facet with no SetRateLimit is UNLIMITED. Requests over the limit are shed with a -429 status before any worker is touched. dans stzAppCluster
  • SetCircuitBreaker Circuit breaker: after nThreshold consecutive failures a worker's circuit OPENS (it is skipped for nCooldownMs, then half-open: one probe re-closes on success or re-opens on failure). dans stzAppCluster
  • SetAuth HTTP auth (Basic by default; libcurl base64-encodes + handles the challenge). Use SetAuthType for digest/ntlm/negotiate/any. dans stzHttpClient
  • SetBearer Bearer / OAuth2 token auth. dans stzHttpClient
  • SetTimeout ── timeouts (engine-backed) ───────────────────────────── These now drive the custom HTTP/1.1 client's per-socket and connect deadlines via the engine, replacing the slice-2 no-ops. dans stzHttpClient
  • SetProxyAuth Proxy credentials, "user:pass". dans stzHttpClient
  • SetUserAgent stzNetwork.init handles its own fields. ── headers / cookies ──────────────────────────────────── dans stzHttpClient
  • SetClientCert mTLS: client certificate + private key (file paths, PEM). dans stzHttpClient
  • SetCookieFile Persistent cookies: read from / write to a Netscape cookie file. dans stzHttpClient
  • SetTraceParent ── distributed tracing (W3C Trace Context) ────────────── Inject a `traceparent` header so downstream services can correlate this request into a single distributed trace (Tier 2 observability). dans stzHttpClient
  • SetDefaultTimeouts Set the process-wide engine defaults (connect / request / idle in ms). 0 leaves a field unchanged. Affects every client. dans stzHttpClient
  • SetMutualTls Run the federation transport over WIRE mTLS: every FederatedCall now goes over a mutually-authenticated, encrypted mbedTLS channel -- this node PRESENTS pcCert/pcKey and VALIDATES the peer's server cert against pcCa (slices 2-3). Combined with governance (SLA) + request signing (per-request auth), this is the full node-to-node security stack: encrypted + mutually cert-authenticated + signed + governed. dans stzComputeFederation

Ajouter

  • AddProfile declaring the fleet composition ------------------------------------ Declare nWorkers processes of a profile (capability tag + caps). One @aFleet row per worker is created NOW (port assigned at Start), so FleetSize/WorkersOf are correct before and after launch. dans stzAppCluster
  • AddFacet Add a profile for a facet DEFINED IN THIS POOL'S CATALOG: capabilities, provenance and external tool are taken from the catalog. dans stzWorkerPool
  • AddActor Register an actor identity (stzSystemActor): the verified key id names the actor whose capability KINDS gate admitted tags. dans stzNode
  • AddKeyword TIER 2: the capability-lexical vocabulary -------------------------- Extend the synonym lexicon (a word that hints a facet). Capability names are matched automatically; keywords add natural phrasing. dans stzRequestClassifier

Parcourir et appliquer

  • RunLocal the running topology ----------------------------------------------- Every node = a child OS process on this machine, under REAL supervision, over the REAL wire (loopback). Same semantics as a multi-machine run; only the latency differs. (D4 scope: the first Supervise() group sets the strategy; every node is supervised.) dans stzNodeApp
  • Run running ------------------------------------------------------------ Thread pInput through every stage in order; each stage's output feeds the next. Returns the final output. Records a per-stage trace. A stage that RAISES is CONTAINED: the failure is traced, the facet slot is released (no leak), the pipeline HALTS and returns NULL, and Why()/ Failed() explain -- one bad stage never crashes the whole pipeline. dans stzComputePipeline
  • RunBatch Run many inputs through the WHOLE pipeline; returns a result list (same order). The trace reflects the LAST input. dans stzComputePipeline
