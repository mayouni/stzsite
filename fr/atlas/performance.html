Performance

Ferme la triade OpenTelemetry, le contrat de service et l'analyse de capacité en un seul plan ; export seulement, ni stockage ni tableaux de bord.

6 Strong · 5 Solid · 1 Partial · 0 Emerging

Mesuré contre : OpenTelemetry · Prometheus · Dossiers : base/perf(s'ouvre dans un nouvel onglet) · Le guide des fonctions de ce domaine

Repensé depuis les premiers principes

Ce que Softanza a gardé de ce qui marche, et ce qu'elle a repensé, tel que la bibliothèque l'a écrit dans ses documents de conception et ses narrations.

La manière SoftanzaLa performance est une chose qu'un programme sait de lui-même : le moteur mesure, le code déclare le budget, et toute action corrective passe par la gouvernance.

Gardé des meilleures pratiques

  • Les données sortent dans des formats ouverts : texte Prometheus, OpenTelemetry (OTLP) et identifiants de trace W3C. Stockage et tableaux de bord restent, à dessein, à ces outils. source(s'ouvre dans un nouvel onglet)
  • L'analyse s'appuie sur les lois classiques : utilisation U = X·D et loi de Little N = X·R. Le temps de réponse est une distribution (p50, p95, p99), jamais une moyenne. source(s'ouvre dans un nouvel onglet)
  • Les durées se mesurent uniquement avec des horloges monotones, insensibles aux corrections de l'heure réseau. L'heure murale sert à dater, jamais à chronométrer. source(s'ouvre dans un nouvel onglet)

Repensé

  • Le budget de performance est du code, déclaré près de ce qu'il juge. Un objectif manqué devient un constat qui fait échouer le build, par la même porte que la sécurité. source(s'ouvre dans un nouvel onglet)
  • Observer librement, agir par la porte. Augmenter la capacité ou redémarrer est un plan gouverné ; un acteur de type modèle de langage peut l'analyser et le proposer, jamais l'exécuter. source(s'ouvre dans un nouvel onglet)
  • Chaque mesure est recoupée par une autre, indépendante : la loi de Little contre les requêtes en cours comptées. Une formule qui ne peut échouer ne prouve rien. source(s'ouvre dans un nouvel onglet)
  • Le moniteur annonce son propre coût : SelfCost() le mesure, un test échoue s'il dépasse une part fixée du travail, et des anneaux de taille fixe gardent la mémoire stable. source(s'ouvre dans un nouvel onglet)

One of the most complete and rigorous planes in the library -- P0-P11 all shipped, 366 assertions -- it closes the OTel triad (metrics + traces + logs, all in native OTLP JSON) and exposes Prometheus text, and adds SLA judgment with edge-triggered alerting, a sampling profiler, queueing-theory capacity analysis and a driven-load harness, in one coherent plane. Its real signature is measurement discipline: clocks as scopes, Windows 15.6 ms quantization handled, self-cost priced, and a rule that unmeasured is an error, never a silent pass. What it is not, by design, is the storage-and-dashboard half.

Ce qu'un artisan en fait, et ce qui se distingue

  • Closes the OTel triad (metrics + traces + logs) and exposes Prometheus text, in one plane
  • Measurement discipline: clocks as scopes, Windows 15.6 ms quantization handled, self-cost priced with its own machinery
  • Unmeasured is an error, never a silent pass
  • Queueing-theory capacity analysis with independent self-checks (utilization, Little's law)

Ce qui est dû

  • Auto-instrumentation (zero-code, opt-out rather than opt-in Observe)
  • Full trace-context propagation (baggage, async-context through reactor jobs, per-task scopes)
  • Head/tail trace sampling; in-process aggregation (PromQL-lite); native-stack profiling
  • A storage/dashboard integration story; macOS RSS; one stale CLAUDE.md metadata line (P0-P7 / 283 vs P0-P11 / 366)

Les fonctions, par ce qu'elles font

Tester et vérifier

  • Check Judging -------------------------------------------------- One judgment pass. Fires alerts on TRANSITIONS only: a rule breaching now that was fine before -> breach alert; a rule fine now that was breached before -> clear alert. Returns the number of NEW breaches this pass. dans stzPerfSentinel
  • CheckAgainst Judging -------------------------------------------------- Judge every expectation against the monitor's MEASURED numbers. Returns the breaches as findings in the unified rule shape ([ :rule, :subject, :where, :severity, :message ], subject "perf") -- hand them to stzRuleReport.Ingest(). Full verdicts (passes included, with actuals) stay readable via Verdicts(). dans stzSla

Compter et mesurer

  • Count Samples ever recorded on this metric. dans stzMetric
  • MeanMs Lifetime mean -- exact (engine keeps the true sum; the buckets quantize, the sum does not). dans stzMetric
  • MaxThroughput Where this machine saturates IF CPU is the constraint (req/s). dans stzPerfProfile
  • Size Samples retained in the window (never exceeds Capacity()). dans stzPerfSeries

Remplacer et modifier

  • Set Gauge face dans stzMetric
  • SetChannels The event-bus channels alerts fan out on (process-global). dans stzPerfSentinel
  • SetBusyMs configuration dans stzLoadDriver

Convertir

  • ToOtelJson One OTLP-style span as a JSON string. dans stzStopwatch
  • ToOtelSpan OpenTelemetry export (industry interop) ------------------ The span as a hashlist in OTel vocabulary. Absolute anchors in unix NANOS as STRINGS (integer ms + "000000" -- exact, since f64 cannot hold epoch nanos); exact ns duration as an attribute. dans stzStopwatch
  • AsWarning Soften the LAST closed expectation: it advises, it does not fail the gate (stzRuleReport.IsSound ignores warnings by convention). dans stzSla
  • ToJson The OTLP resourceSpans envelope, every collected span inside. dans stzOtelBatch

Lire et écrire

  • LoadRatio The demand signal for elastic scaling (perf P6): how close this workload is to its CPU ceiling, X/Xmax in 0..1. This is what stzClusterSupervisor.ReportLoad() always wanted -- MEASURED, not hand-fed: FeedLoadFrom(tag, oProfile) closes the loop. 0 when nothing is measurable yet (no requests / no demand). (Named LoadRatio: `load` is a Haro keyword.) dans stzPerfProfile

Parcourir et appliquer

  • RunFor Standalone continuous mode: drive the cadence for nMs (blocking; for scripts and guards -- servers should host, not block). dans stzPerfMonitor
  • ExecuteOn The crossing (admission is governed) --------------------- Apply the plan to the target -- a stzAppCluster, or any object answering ScaleUp(tag)/ScaleDown(tag)/RestartDead() (a double in rehearsal, per the service-virtualization pattern). Returns the number of actions committed; 0 with a full refusal audit when the actor may not commit. dans stzPerfPlan
