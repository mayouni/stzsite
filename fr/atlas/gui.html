Interface et réactif

Un jeune plan RmlUi, remarquable en droite-à-gauche et en accessibilité ; le moteur réactif n'est pas encore relié à la vue.

2 Strong · 6 Solid · 4 Partial · 0 Emerging

Mesuré contre : Qt · GTK · Flutter · React · Dossiers : base/gui(s'ouvre dans un nouvel onglet) · base/reactive(s'ouvre dans un nouvel onglet) · base/app(s'ouvre dans un nouvel onglet) · Le guide des fonctions de ce domaine

Pas encore d'image. Le plan des interfaces est jeune et pas encore publié ; ses images viendront de ses propres gardes.

Repensé depuis les premiers principes

Ce que Softanza a gardé de ce qui marche, et ce qu'elle a repensé, tel que la bibliothèque l'a écrit dans ses documents de conception et ses narrations.

La manière SoftanzaLes déclarations Softanza font contrat ; le balisage que lit le moteur d'interface n'en est qu'une projection, générée et jamais écrite à la main.

Gardé des meilleures pratiques

  • La mise en page et la saisie viennent de RmlUi plutôt que d'une boîte à outils maison. Il a été choisi pour sa licence permissive, son rendu fourni par l'hôte, l'absence de JavaScript et un vrai modèle de saisie. source(s'ouvre dans un nouvel onglet)
  • Le format de description reprend une idée de QML : chaque élément est un nom doté de propriétés typées. Les éléments anonymes imbriqués sont refusés, donc chaque boîte a un nom. source(s'ouvre dans un nouvel onglet)
  • Le travail asynchrone repose sur libuv, boucle d'événements multiplateforme éprouvée, plutôt que sur un réacteur fait maison. Les scripts soumettent et récupèrent leur travail, sans jamais être rappelés. source(s'ouvre dans un nouvel onglet)

Repensé

  • Le balisage est généré, jamais écrit à la main. Un fichier .panel fait contrat ; RmlUi et HTML n'en sont que des projections, car le balisage manuel échappe aux contrôles. source(s'ouvre dans un nouvel onglet)
  • L'arbre d'accessibilité est produit à partir de l'intention déclarée, non deviné depuis le balisage, ce qui informe mieux les lecteurs d'écran. Tout élément focalisable a un rôle et un nom. source(s'ouvre dans un nouvel onglet)
  • Le code réactif s'exprime en mots simples, des fonctions qui attendent, des valeurs qui se mettent à jour seules, plutôt qu'en métaphores comme rappels et abonnés, qui masquent un flux simple. source(s'ouvre dans un nouvel onglet)
  • Une application est un monde vivant, porteur de sens : un domaine, une vie tendue vers des buts, un corps. Fichiers, base de données et interface n'en sont que la tuyauterie. source(s'ouvre dans un nouvel onglet)

A young but genuinely coherent GUI plane, built on vendored RmlUi and actually running — windows open, events flow, it renders through the GPU plane and an SVG tier. Two standouts reflect the library's DNA: RTL/bidi fully owned and accessibility built in from the grammar up. The rest is early: a four-primitive vocabulary, flexbox-only layout, imperative view-binding, and a full reactive runtime that ships but is not yet wired to the GUI. The whole plane is on local main only, not yet pushed.

Ce qu'un artisan en fait, et ce qui se distingue

  • RTL/bidi fully owned end to end
  • accessibility mandatory at authoring time, exposed via AccessKit
  • a recorder-not-painter render model with a deviceless SVG tier
  • an event surface that counts dropped events

Ce qui est dû

  • wire the reactive runtime to the GUI (G5 clause 2)
  • a richer widget set
  • the semantic theme system (G6)
  • IME & two-way text editing

La manière Softanza, exécutée

Ce que Softanza fait autrement dans ce domaine, montré par du code tiré de ses narrations et de ses gardes, et exécuté pour cette page.

Un seul mot déclaré, rtl, est traduit dans la propriété de direction propre au moteur : l'auteur n'écrit jamais le balisage du moteur à la main.

Softanza
oRtl = new stzUiDocument(
	'DEFINE PANEL p ( FONT "app", CHILDREN [r] ) RATIONALE "x"' + char(10) +
	'DEFINE BOX r ( TEXT_DIRECTION rtl, HEIGHT 20 ) RATIONALE "x"')
chk("TEXT_DIRECTION rtl becomes --rmlui-direction",
    StzFindFirst("--rmlui-direction: rtl", oRtl.ToRml()) > 0)
chk("...and never the CSS spelling RCSS rejects",
    StzFindFirst("; direction:", oRtl.ToRml()) = 0)
Sortie
  [OK] TEXT_DIRECTION rtl becomes --rmlui-direction
  [OK] ...and never the CSS spelling RCSS rejects

Une application se déclare comme un monde de choses, de vérités et de relations, et elle s'explique elle-même en texte clair.

Softanza
oApp = new stzApp("SonibankVisits")
oApp {
    AddThingQ(:Account) { Has([ :number, :chapter, :balance ])  IsTrue(:balance, "@ >= 0") }
    AddThingQ(:Client)  { Has([ :code, :name, :city ])  Owns(:Account) }
    AddThingQ(:Visit)   { Of(:Client)  Has([ :agent, :date, :subject ]) }
    AddRelation(:Account, :belongsTo, :Client)
}
oApp.Explain()

RTL & bidirectional text

Accessibility
Strong
G4a: a mandatory RATIONALE on every element emits an ARIA-role tree; G4b: a11y.zig hands that tree to AccessKit (UIA / NSAccessibility / AT-SPI)stzAccessibilityTree / a11y.zig
Declarative authoring (.panel)
Solid
A closed four-kind grammar PANEL/BOX/TEXT/STYLE, a diagnostics court, a .panel->RML->.panel round-trip fixpoint; far narrower than peer component modelsstzUiDocument
Layout
Solid
RmlUi flexbox via RCSS: direction, wrap, gap, align, justify, px/%/fill sizing; CSS Grid refused by decision, no constraint or custom layoutstzUiDocument::ToRml()
Rendering backend
Solid
RmlUi's render interface is a recorder, not a painter (stz_rmlui.cpp): one flat display list drawn by the GPU tier or an SVG tier; PNG needs a GPU devicestz_rmlui.cpp
Event handling
Solid
Pointer, key, text-input, focus and directional focus move, hit-testing (element_at), an event recorder that counts dropped events; no gesture recognitionstzPanel
Reactive runtime & signals
Solid
stzReactiveObject with Watch / Computed(deps) / BindTo / SetAttribute, streams, timers, HTTP, event bus on a libuv reactor; not yet reaching the viewbase/reactive; reactor.zig
App shell & windowing
Solid
Native windows via vendored GLFW (window.zig); stzApp is a declarative living world; no multi-window orchestration, dialogs, menus or system-traywindow.zig / stzApp
Widget / element toolkit
Partial
RmlUi's own form controls (input, select, textarea, progress, tabset, button); no tables, trees, menus, dialogs, pickers, toolbars, docking
State->view binding
Partial
{placeholder} templates and Set/SetStyle/Apply mutate a live document preserving focus, values escaped as data; imperative, not reactivestzUiBindings (G5 clause 1)
Text input & IME

Single-line text input works (stz_gui_text_input); no IME, composition input for CJK and complex scripts deferred (costed at 1-3 engineer-years)
Theming & animation
Partial
Inline styling (BACKGROUND, COLOR, STYLE bags -> RCSS) and a profile layer; no semantic theme system (G6 not started) and no animation/transitions

Les fonctions, par ce qu'elles font

Tester et vérifier

  • IsStrictWidth Is this element's geometry DECLARED, rather than measured from its text? Only a declared one is a strict observable -- see StzUiProfileIsStrictBox. dans stzUiDocument
  • IsStrictlyPlaced A box sits where its predecessors left it, so its POSITION is only claimed when it and every earlier sibling fix their own size. dans stzUiDocument
  • IsBeingRead TRUE when something has read the tree at least once -- which is the only evidence available in-process that a screen reader is there. dans stzScreenReaderBridge
  • CheckAndTick Drive the timer from the manager's poll loop. Returns isActive so the manager can prune completed one-shot timers. dans stzReactiveTimer

Trouver

  • LastErrorWhere Which operation failed -- "Batch", "Watcher:name", "Computed:greeting"... dans stzReactiveObject
  • LastEvent The most recent payload emitted on the channel ("" if none). dans stzEventBus

Remplacer et modifier

  • SetTime RmlUi's clock, driven by the caller -- so a test frame is deterministic instead of depending on when it ran. dans stzPanel
  • SetTextOf The difference is measurable, and the guard measures it: after a rebuild every string is generated again; after a set, only the ones that actually changed are. GenerateCalls() reports both. One element's words. The value is DATA -- it is escaped at the seam, so a model holding "<span>" cannot inject markup into a document the court already passed. dans stzPanel
  • SetStyleOf An EMPTY value removes the property, handing the element back to the stylesheet. Without that, a binding that had fired once could never be undone. dans stzPanel
  • SetBody == BODY (embodiment) ==================================================== SetBody() returns This; the brace assigns the body-cursor attributes (Graph_/Files/Keep_ -- note: the DSL keywords Graph and Keep collide with the Graph() accessor and the Keep(thing) flow verb, so the ATTRIBUTES carry a trailing underscore and BraceEnd reads whichever was written). dans stzApp
  • SetAsync Async Attribute update dans stzReactiveObject
  • SetAttribute Universal Attribute setter dans stzReactiveObject
  • SetAutoConcludeDelay It used to take anything at all: -500 and "not a number" both went straight through to a timer deadline. A refused value leaves the delay ALONE rather than resetting it -- a setter that answers a value it dislikes by destroying a good one is its own defect. dans stzReactiveStream
  • Set the one verb -------------------------------------------------------- Give a name a value. Every element whose template mentions it is re-rendered and set; nothing else is touched. dans stzUiBindings
  • SetStyle Text updates re-shape the whole document; style updates do not. Kept as its own verb rather than folded into Set(), because the two have genuinely different costs and a caller choosing between them should see which is which. dans stzUiBindings
  • SetReactor NOTE: the stored reactor is a COPY (Haro attribute assignment copies objects) that SHARES the engine handle -- safe because the handle is never destroyed while a system lives (see stzReactive. Stop). The http drain is NOT stored for the same reason: a copy's aPending would be a dead snapshot; RunLoop takes the LIVE object as a parameter instead (params are by-reference). dans stzTimerManager
  • SetPatience HOW MANY consecutive idle iterations the loop tolerates before it stops. A count, not a duration -- RunLoop compares it against _emptyLoopCount_. Zero is meaningful and is the default (PATIENCE_NONE, mirroring libuv's uv_run: return as soon as there is no work), so only negatives and non-numbers are refused. dans stzTimerManager
  • SetCheckFrequency A refused value leaves the old one alone. Answering a bad value by destroying a good one is its own defect. dans stzTimerManager

Retirer

  • ClearAll Handy for test isolation, and worth saying plainly: the bus is PROCESS-GLOBAL, so this resets channels other parts of the same process are watching, and their event counts restart at zero. See EventCount. dans stzEventBus
  • ClearStyle Hand the element back to the stylesheet. dans stzUiBindings

Ajouter

  • AddFlow == LIFE - BEHAVIOR (Becoming) =========================================== When() returns This: the brace { Require(:x) Then( Keep(:Y) ) } runs app methods against the current-flow cursor. dans stzApp
  • AddGoal == LIFE - PURPOSE (Becoming) ============================================ AddGoal() returns This; the brace assigns the goal-cursor ATTRIBUTES (Means/ReachedBy/Within/Respecting), flushed into the record by BraceEnd() when the brace closes. dans stzApp
  • AddThing == DOMAIN (Being) ======================================================= AddThing() performs the act and returns NOTHING; AddThingQ() performs it and hands back the app, so the block AddThingQ(:X) { Has(...) Owns(:Y) } runs the app's OWN Has/IsTrue/Owns/Of on the current-thing cursor. (The core law: a plain name acts, the Q chains -- exactly as stzList does with AddItem() / AddItemQ().) dans stzApp
  • AddScreen == EMERGENTS (met from without) ========================================= dans stzApp
  • AddTask Manages tasks, streams, and timers for internal system operations. dans stzReactiveSystem
  • AddTimer internal methods dans stzReactiveSystem
  • AddStream internal methods dans stzReactiveSystem
  • AddWorld the registry: worlds as nodes dans stzSuperApp
  • AddConstellation recursion: a constellation may contain another constellation dans stzSuperApp

Ordonner et déplacer

  • Swap HOT-SWAP a live world's implementation, keeping its node + bonds. dans stzSuperApp

Convertir

  • ToCanvas The panel as a picture, on the tier this machine can reach. A canvas is made, drawn into and answered -- so the caller gets ToSVG/ToPNG/ Show without assembling anything. dans stzPanel
  • FromWindow the conversions, named at the boundary ------------------------------ A window's pixels are the panel's when the panel fills the window, which is the case stzWindow.Draw arranges. Named anyway: the reader of a frame loop should see WHERE the space changes. dans stzPanel
  • FromTexture A panel hanging in a 3D scene is hit by a RAY, and what the caller has after the intersection is a texture coordinate. This is the whole of the in-scene input mapping (§6's tier): uv in, panel pixels out. v is flipped because a texture's origin is bottom-left and a panel's is top-left -- the one place that difference is stated, so no caller has to remember it. dans stzPanel
  • ToRml the projection ------------------------------------------------------ The RML this document means. The defaults here are §4b's table: every divergence G1 found is absorbed so the author never sees it. dans stzUiDocument
  • ToHtml THIS SHARES EVERY RULE WITH ToRml. The two projections differ only where stzUiProfile records a DIVERGENCE, and they ask the profile for the spelling rather than carrying their own copy -- which is the whole reason the profile had to become data. If the shared half ever forks, the fixture below is what says so. dans stzUiDocument
  • ToText the canonical print (round-trip fixpoint) dans stzUiDocument
  • ToFixture paNativeBoxes is [ [ name, x, y, w, h ], ... ] from the laid-out panel -- BoxOf() for every named element. dans stzUiDocument
  • ToJSON the tree as DATA ---------------------------------------------------- Rule 104: "what a screen reader can operate, an agent can operate." A tree that only a C++ adapter can read serves the first and not the second, so it goes out as JSON -- inspectable, diffable, assertable in CI, and the shape an adapter of any language can consume. dans stzAccessibilityTree

Afficher, dessiner et mettre en forme

  • BoxOf The laid-out box of one element: [x, y, w, h], in panel pixels. Empty when there is no such element -- an absence, not a raise, since asking about an element that may not exist is a fair question. dans stzPanel
  • DrawInto output -------------------------------------------------------------- Put the panel's triangles into a canvas. The canvas decides what happens next -- ToSVG() with no device, ToPNG() with one, a window, or a texture mapped onto a quad in a 3D scene. The panel does not know and must not care. dans stzPanel
  • RenderOf What one element's text would be, right now. Inspectable without touching the panel, which is what makes the substitution testable separately from the rendering. dans stzUiBindings

Lire et écrire

  • LoadMarkup the document -------------------------------------------------------- Markup as a STRING, because markup is emitted. See the header. dans stzPanel
  • OpenCommonsOn the Commons (world zero) ------------------------------------------- Back the shared Commons with an open stzDatabase. dans stzSuperApp

Parcourir et appliquer

  • Filter Store filter transformation with expressive constant dans stzReactiveStream
  • Apply Push every template again, whatever changed. What a caller does after loading a screen, to fill it in one go. dans stzUiBindings
  • RunLoop poHttpDrain = the LIVE stzReactiveHttp object (by-ref param; an attribute copy would drain a dead snapshot). NULL = no http. dans stzTimerManager
  • PerformHttpGet This is the path taken when there is no reactor -- which is exactly what SetReactor(NULL) selects, and what the reactor switch falls back TO. The switch had an off position that could not work. dans stzHttpTask
