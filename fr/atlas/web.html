Web et serveur d'applications

Un serveur HTTP compétent, avec un contrat de service intégré, l'authentification et un fournisseur d'identité, et un plan de virtualisation de services qui refuse les faux.

4 Strong 5 Solid 2 Partial 1 Emerging

Où il en est

La lecture du Compas Softanza : chaque couloir du domaine noté face au meilleur de sa catégorie, d'après ce que les gardes prouvent (Read from the source on 2026-09-16, from a read-only main worktree). Les phrases du Compas sont en anglais, telles qu'il les a écrites.

Two things live here, and the distinctive one isn't the web server. The HTTP server is real and competent — a reactor-driven HTTP/1.1 server with Express-like routing, built-in HTTPS/mTLS, an auto-CRUD sqlite backend, and (ahead of Express and FastAPI) a built-in per-request SLA bracket with Prometheus /metrics + distributed tracing, plus a mounted auth router that is also an OIDC provider. But it's missing modern-API table stakes: middleware is registered-but-never-invoked, no JSON request-body parsing, no streaming, no WebSocket. The standout is the service-virtualization plane — WireMock-and-beyond stateful doubles under a governance gate no competitor has: Deploy(:Production) structurally refuses a fake dependency, even for a fully-entitled human.

The honesty line on the ratings. Re-surveyed from main. The reactor server, MBaaS CRUD and IoT listener are guarded by real end-to-end narrated tests (a second reactor as the client, sqlite persistence verified), and the service plane is heavily guarded (~370 assertions — registry, ports, delivery — living under test/system, since test/service is empty). Two things to note: three legacy appserver tests fail with a C22 function-redefinition (structural, not behavioral — the narrated guards are what vouch for the server), and two capabilities (middleware, static) are registered but never executed — the advertised surface exceeds the wired one. A critical governance bug is fixed and recorded: the registry once snapshotted state and could fail open on a later fake-bind; it is now keyed by id so every copy is the registry.

The one-sentence position. Softanza's web tier is a competent-not-remarkable HTTP server whose real distinction is everything around the request — built-in SLA observability, a built-in auth provider, and a stateful service-virtualization plane gated so a fake can't reach production — while its distance from Express/FastAPI is the ergonomic middle (middleware, JSON bodies, streaming, WebSocket, OpenAPI) it has scoped but not fully wired.

Ce qu'un artisan en fait, et ce qui se distingue

  • A built-in per-request SLA bracket with Prometheus /metrics and distributed tracing, ahead of Express and FastAPI
  • A mounted auth router that is also an OIDC provider (discovery, JWKS, authorize, PKCE token)
  • Stateful service doubles that enforce the real service's rules -- WireMock-and-beyond
  • Deploy(:Production) structurally refuses a fake dependency, even for a fully-entitled human

Ce qui est dû

  • Execute the middleware pipeline (registered but never invoked)
  • JSON request bodies and streaming responses
  • Serve static files; WebSocket serving; latency injection and a status-aware live adapter in the sandbox
  • OpenAPI/schema and content negotiation; server-side HTTP/2; deeper MBaaS

Repensé depuis les premiers principes

Ce que Softanza a gardé de ce qui marche, et ce qu'elle a repensé, tel que la bibliothèque l'a écrit dans ses documents de conception et ses narrations.

La manière SoftanzaLe serveur est un hôte, pas une bibliothèque appelée à chaque requête : le moteur est déjà chargé et prêt, et le serveur ne fait qu'y amener les requêtes et en rapporter les résultats.

Gardé des meilleures pratiques

  • Le routage reste simple : une table méthode, chemin, gestionnaire, avec des paramètres comme /user/:id et un joker final. Les routes exactes passent en premier. source(s'ouvre dans un nouvel onglet)
  • La connexion suit les standards publiés : OpenID Connect, clés d'accès, SAML, codes à usage unique. Le jeton change dès que la session gagne des droits, contre la fixation de session. source(s'ouvre dans un nouvel onglet)
  • Un back-end de données, c'est du REST sur la base SQLite intégrée : Expose(db, table) fournit lister, lire, créer, modifier, supprimer, à l'abri des injections, avec de vrais 404. source(s'ouvre dans un nouvel onglet)

Repensé

  • Le moteur est résident : aucun démarrage à froid, donc nulle grappe pour rester « chaud ». Les workers ne servent qu'à la concurrence et à l'isolement de charge. source(s'ouvre dans un nouvel onglet)
  • Un hôte, quatre formes : routes web, back-end de données, flux bruts d'objets connectés et agents hébergés. Les agents partagent la boucle d'événements du serveur, sans runtime séparé. source(s'ouvre dans un nouvel onglet)
  • Une connexion ne pose pas un drapeau et ne renvoie pas un simple rôle : elle produit un acteur, avec capacités et niveau de confiance, que tout le programme comprend. source(s'ouvre dans un nouvel onglet)
  • On code toute l'application contre des bacs à sable fidèles, puis on passe aux vrais services au déploiement. Le registre interdit un bac à sable en production. source(s'ouvre dans un nouvel onglet)

La manière Softanza, exécutée

Ce que Softanza fait autrement dans ce domaine, montré par du code tiré de ses narrations et de ses gardes, et exécuté pour cette page.

Une connexion renvoie un acteur doté de capacités et d'un niveau de confiance, pas un rôle en texte.

NOW = 1700000000   # a fixed clock, as in the guard
a = new stzAuth()
a.Register("dana", "pw")
a.GrantRole("dana", "admin")
tok = a.LoginAt("dana", "pw", NOW)
act = a.ActorOfAt(tok, NOW)
? "user        : " + act.Name()
? "capabilities: " + @@(act.Kinds())
? "posture     : " + act.Posture()

12 couloirs, chacun face au meilleur de sa catégorie

Pour chaque couloir : ce qui tourne dans le moteur aujourd'hui, les outils contre lesquels il est juste de le mesurer, et ce qui reste dû.

01Request bracket & SLA observabilityStrong

In the engine

A per-request bracket around parse→route→handler→write recording well-known subjects http.request.ms / http.requests / http.errors and a labeled http.route.ms family, over engine histograms (p50/p95/p99). Built-in /health and Prometheus /metrics, plus W3C traceparent propagation.

Measured against

Express (add-ons)FastAPI (instrumentation)OpenTelemetry

To complete

Observability is built in, not bolted on — ahead of Express/FastAPI, which need middleware libraries for the same. Per-route percentiles and tracing ship by default.

02Auth, OIDC & sessionsStrong

In the engine

MountAuth serves login / 2FA / logout / magic-link / OTP with HttpOnly + SameSite cookies and CSRF; MountOidcProvider makes the server an IdP (discovery, JWKS, authorize, PKCE token); off-loopback listeners take RequireSignedRequests (HMAC, clock-skew, nonce replay).

Measured against

Express + passportFastAPI + authlibKeycloak

To complete

An auth router and an OIDC provider built into the server — beyond what Express/FastAPI ship. Wired to the security plane's stzAuth / stzRequestSigner.

03Stateful service doublesStrong

In the engine

Behavior-accurate sandboxes, not just canned responses: a payment state machine (authorize→capture-once, refund≤captured, integer minor units, assertable ledger), an LLM double with cost accounting, mail/SMS capture sinks (SMS counts billable segments), a local-real blob store, and real signing OIDC/passkey doubles.

Measured against

WireMock scenariosStripe test modespecialized mocks

To complete

These enforce the rules of the real service (you cannot capture twice, refund more than you took) — well beyond WireMock's response stubbing. A genuinely distinctive testing surface.

04Deploy(:Production) refuses fakesStrong

In the engine

Every bound service carries a posture (sandbox / local / live); five registry invariants (sandbox-in-production, live-without-secret, ephemeral-in-production…) plus part-level graph rules. At the crossing, stzDelivery.Deploy refuses even a fully-entitled human if the surface is unsound, logs an incident, and returns a rehearsal.

Measured against

WireMock (none)Express (none)config discipline

To complete

"Shipping a fake payment gateway is not an authority question." No peer has a structural gate that makes fakes-in-production unrepresentable — and the fail-open snapshot bug that once broke it is fixed and guarded.

05HTTP server (accept · route · respond)Solid

In the engine

A real HTTP/1.1 server: the engine (reactor.zig + http_framing.zig) does async accept + framing on the libuv thread; Haro drains events and dispatches synchronously (ServeOne / Run), with keep-alive and Connection: close handling.

Measured against

ExpressFastAPIGo net/http

To complete

HTTP/1.1 only server-side (HTTP/2 is client-only, via curl), and one request per ServeOne — no concurrent in-Haro handling. A genuine server, at a single-threaded dispatch tier.

06RoutingSolid

In the engine

stzAppRouter: Get_/Post/Put_/Delete, path params (:id, multi-param), trailing * wildcard, exact-first then first-pattern-wins.

Measured against

Express routerFastAPI paths

To complete

Express-shaped and works, but no route groups, no regex constraints on params, and no method-not-allowed vs not-found distinction.

07TLS / HTTPS / mTLS servingSolid

In the engine

StartTls / StartHttps with mbedTLS termination below the router, and mutual TLS (bRequireClient + CA path) — handlers run on decrypted bytes.

Measured against

nginx (Express/FastAPI defer to it)Go ListenAndServeTLS

To complete

HTTPS + mTLS built in, where Express/FastAPI usually delegate TLS to a reverse proxy. Test certs only — no managed cert lifecycle (shared with the concurrency plane's mTLS note).

08Auto-CRUD backend (MBaaS)Solid

In the engine

Expose / ExposeWithKey generate a full REST CRUD surface over sqlite — /api/&lt;table&gt; list / count / read / create / update / delete, SQL-escaped.

Measured against

PostgRESTSupabaseFirebase

To complete

A genuine auto-backend Express/FastAPI don't ship — but sqlite-only and basic: no relations, filtering, pagination or projection depth.

09HTTP mocking (record / replay / journal)Solid

In the engine

stzHttpSandbox: Script (exact / prefix / contains matching), canned + JSON + failure responses, record/replay keyed by sha256(method|url|body) (a recording wins over a script), strict-by-default (unscripted requests raise), and a journal (NumberOfCallsTo catches retry storms).

Measured against

WireMocknock / VCRMountebank

To complete

Matching is three patterns (no header / body / regex matchers WireMock has), there is no latency injection, and the live adapter reports only 200/0 (no status line from the curl client).

10Request & response objects, body parsingPartial

In the engine

stzAppRequest (Query / Header / Body / Param, case-insensitive headers, form-urlencoded parse) and stzAppResponse (Status / Header / Json / Text / Html / Send).

Measured against

Express req/resFastAPI (Pydantic)

To complete

No JSON request-body parsing (only serialize-out), no multipart, and no streaming responses (the body is always buffered with a fixed Content-Length). Real gaps for a modern JSON API.

11Modern API table stakesPartial

In the engine

Static routes and hosted-agent surfaces are registered; /health and /metrics ship.

Measured against

FastAPI (OpenAPI / WS native)Express (middleware)

To complete

Absent: WebSocket serving, OpenAPI/schema, content negotiation, server-side rate limiting, templating — and static file serving is registered but never served. The breadth FastAPI/Express are chosen for.

12Middleware pipelineEmerging

In the engine

Use / AddMiddleware store handlers in @aMiddleware.

Measured against

Express (app.use chain)FastAPI dependencies

To complete

The middleware is registered but never invoked — _Dispatch has no execution path for @aMiddleware. Middleware is the Express model, so this is the biggest single missing mechanism: without it, cross-cutting concerns (CORS, logging, auth guards) can't compose.

Ce qui est dû, dans l'ordre du rendement

Les manques, classés par ce qu'ils rapportent et non par leur taille ; la valeur est l'effet sur la portée de la bibliothèque, l'effort une lecture d'ingénieur.

Tier A — wire what's half-there

Execute the middleware pipeline

Use/AddMiddleware already store handlers — _Dispatch just never runs them. Wiring the chain (before/after route) is the single highest-leverage fix: it turns CORS, logging, auth-guards and rate-limits from impossible into one-liners.

Valeur · élevéeEffort · faible
JSON request bodies + streaming responses

Parse an inbound JSON body into a value (today only form-urlencoded parses; JSON is serialize-out only), and stream a response instead of always buffering to a fixed Content-Length. Both are table stakes for a JSON/API server.

Valeur · élevéeEffort · moyen

Tier B — real-time & the mocking edges

Serve static files

Static/AddStaticRoute are registered into @aStaticRoutes but nothing serves them. Finish the dead path — a small, expected capability.

Valeur · moyenneEffort · faible
WebSocket serving

Server-side WebSocket over the reactor — absent today. Needed for any real-time surface (live dashboards, agent streams, the GUI reactive layer over the wire).

Valeur · moyenneEffort · moyen
Latency injection + a status-aware live adapter

The HTTP sandbox's two WireMock-parity gaps: a delay knob for latency/timeout simulation, and a live client that returns the real status line (today only 200/0). Small, and they complete the record/replay story.

Valeur · moyenneEffort · faible

Tier C — FastAPI-grade breadth

OpenAPI, schema & content negotiation

Body-schema validation, a generated OpenAPI document, and Accept/Accept-Language handling — the FastAPI surface that turns routes into a documented, validated API.

Valeur · moyenneEffort · moyen
HTTP/2 (server) & richer matching

Server-side HTTP/2 (the client already has it via curl+nghttp2), and header/body/regex request matchers in the sandbox toward full WireMock parity.

Valeur · moyenneEffort · élevé
Deeper MBaaS

Relations, filtering, pagination and projection on the auto-CRUD backend, and a datasource beyond sqlite — the step from a demo backend to a deployable one.

Valeur · moyenneEffort · moyen
