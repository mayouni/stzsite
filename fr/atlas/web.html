Web et serveur d'applications

Un serveur HTTP compétent, avec un contrat de service intégré, l'authentification et un fournisseur d'identité, et un plan de virtualisation de services qui refuse les faux.

4 S5 So2 P1 E

Mesuré contre: Express · FastAPI · WireMock · Dossiers: base/appserver · base/service · La page d'origine de l'Atlas

Two things live here, and the distinctive one isn't the web server. The HTTP server is real and competent -- reactor-driven HTTP/1.1, Express-like routing, built-in HTTPS/mTLS, auto-CRUD sqlite, and ahead of Express and FastAPI a built-in per-request SLA bracket plus an auth router that is also an OIDC provider -- but middleware is registered-but-never-invoked, with no JSON body parsing, streaming or WebSocket. The standout is the service-virtualization plane: stateful doubles under a governance gate where Deploy(:Production) structurally refuses a fake dependency, even for a fully-entitled human.

Ce qu'un maker en fait, et ce qui se distingue

  • A built-in per-request SLA bracket with Prometheus /metrics and distributed tracing, ahead of Express and FastAPI
  • A mounted auth router that is also an OIDC provider (discovery, JWKS, authorize, PKCE token)
  • Stateful service doubles that enforce the real service's rules -- WireMock-and-beyond
  • Deploy(:Production) structurally refuses a fake dependency, even for a fully-entitled human

Ce qui est dû

  • Execute the middleware pipeline (registered but never invoked)
  • JSON request bodies and streaming responses
  • Serve static files; WebSocket serving; latency injection and a status-aware live adapter in the sandbox
  • OpenAPI/schema and content negotiation; server-side HTTP/2; deeper MBaaS

Les couloirs, un par un

Les couloirs et leurs notes sont cités dans la langue de l'Atlas, l'anglais, tels qu'ils ont été lus à la source. lu à la source le Read from the source on 2026-09-16, from a read-only main worktree.

Request bracket & SLA observability
Strong
Per-request bracket recording http.request.ms/requests/errors and http.route.ms over engine histograms (p50/p95/p99); built-in /health, /metrics, traceparent.histogram.zig; well-known subjects http.request.ms, http.requests, http.errors
Auth, OIDC & sessions
Strong
MountAuth serves login/2FA/magic-link/OTP with HttpOnly+SameSite cookies and CSRF; MountOidcProvider makes the server an IdP; signed requests off-loopback.stzAuth, stzRequestSigner
Stateful service doubles
Strong
Payment state machine (capture-once, refund <= captured), LLM double with cost accounting, mail/SMS sinks, blob store, real-signing OIDC/passkey doubles.stzPaymentsPort; SOFTANZA_SERVICE_VIRTUALIZATION_PLAN.md
Deploy(:Production) refuses fakes
Strong
Every bound service carries a posture; five registry invariants plus graph rules; stzDelivery.Deploy refuses even a fully-entitled human if unsound.base/system/stzDelivery, stzServiceRegistry, stzServiceRule; ~370 assertions under test/system
HTTP server (accept, route, respond)
Solid
Real HTTP/1.1: async accept + framing on the libuv thread, Haro dispatches synchronously (ServeOne/Run), keep-alive; HTTP/1.1 only, single-threaded dispatch.reactor.zig, http_framing.zig, stzAppServer
Routing
Solid
stzAppRouter: Get_/Post/Put_/Delete, path params, trailing * wildcard, exact-first then first-pattern-wins; no route groups, regex constraints or 405 vs 404.stzAppRouter
TLS / HTTPS / mTLS serving
Solid
StartTls/StartHttps with mbedTLS termination below the router and mutual TLS (bRequireClient + CA path); test certs only, no managed cert lifecycle.
Auto-CRUD backend (MBaaS)
Solid
Expose/ExposeWithKey generate REST CRUD over sqlite (/api/<table> list/count/read/create/update/delete); sqlite-only, no relations, filtering or pagination.stzAppBackend, db.zig
HTTP mocking (record / replay / journal)
Solid
stzHttpSandbox: Script matching, record/replay keyed by sha256(method|url|body), strict by default, a journal; no header/body/regex matchers, no latency knob.stzHttpSandbox, stzHttpPort
Request & response objects, body parsing
Partial
stzAppRequest (Query/Header/Body/Param, form-urlencoded) and stzAppResponse (Status/Header/Json/Text/Html/Send); no JSON body parsing, multipart or streaming.stzAppRequest, stzAppResponse
Modern API table stakes
Partial
/health and /metrics ship; WebSocket serving, OpenAPI, content negotiation, rate limiting, templating absent; static files registered but never served.
Middleware pipeline
Emerging
Use/AddMiddleware store handlers in @aMiddleware but _Dispatch has no execution path for them: registered but never invoked.stzAppServer _Dispatch / @aMiddleware
