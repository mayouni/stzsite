Diagrammes et graphes

Vingt-cinq notations sur un seul moteur de rendu, un moteur de graphes de niveau NetworkX et une mise en page résolue par contraintes.

4 S5 So3 P

Mesuré contre: Graphviz · Mermaid · D2 · NetworkX · Dossiers: base/graph · La page d'origine de l'Atlas

One of the most complete planes in the library: 25 notations all rendered by one engine, over a native deterministic layout engine and a NetworkX-tier graph-algorithm suite; math and molecule diagrams are genuinely constraint-solved via autodiff. The old dot.exe dependency is demoted to an optional viewer — diagram layout is now engine-native. Guarded by ~1,790 assertions.

Ce qu'un maker en fait, et ce qui se distingue

  • 25 notations as data profiles over one renderer
  • determinism as a guarantee: bit-identical layout across processes
  • constraint-solved layout via autodiff, which no mainstream tool does
  • NetworkX-core parity, compiled

Ce qui est dû

  • meet the dot kill criterion (spline routing, nested clusters)
  • live interactivity via the GUI plane
  • graph generators & isomorphism
  • PDF / PostScript export

Un exemple, exécuté

Un graphe orienté de cinq villes ; le plus court chemin est demandé, pas calculé à la main.

Softanza
oG = new stzGraph("roads")
for cTown in [ "Niamey", "Dosso", "Maradi", "Zinder", "Tahoua" ]
    oG.AddNode(cTown)
next
oG.AddEdge("Niamey", "Dosso")
oG.AddEdge("Dosso", "Maradi")
oG.AddEdge("Maradi", "Zinder")
oG.AddEdge("Niamey", "Tahoua")
oG.AddEdge("Tahoua", "Zinder")
? oG.NumberOfNodes()
? oG.NumberOfEdges()
? @@( oG.Neighbors("Dosso") )
? oG.IsConnected()
? @@( oG.ShortestPath("Niamey", "Zinder") )

Notation breadth
Strong
25 notations (DN0-DN24), ~21 Haro faces, all as profiles over one renderer (stzDiagram), not separate tools; the domain list is closed by designstzDiagram; SOFTANZA_GRAPH_PLANE_PLAN.md DN0-DN24
Deterministic layout engine
Strong
graph_layout.zig (GG1): barycentre crossing-reduction, seeded Fruchterman-Reingold force, bit-identical within and across processesgraph_layout.zig; determinism guard
Graph algorithms
Strong
graph.zig (CSR): BFS/DFS, Dijkstra, A*, SCC, bridges, toposort, betweenness/closeness/PageRank/k-core/Louvain, MST, max-flow/min-cut; engine-implementedgraph.zig; test/graph (158 files)
Constraint-solved diagrams
Strong
Math (DN7) and molecule (DN11) layouts are solved by the engine's autodiff solver (StzEngineGrad*), with DragTo/Pin interactive re-solvesolver/constraint/autodiff.zig
Rendering & output
Solid
One renderer, three outputs: ToSVG (no device), ToPNG (GPU-backed), an ASCII visualizer; 24 node shapes; DOT export; no PDF/PostScript
Diagram editing & interactivity
Solid
Command-based edit session: Edit, Undo/Redo, EditLog, PickAt, RewireAnchor; illegal edits refused at the gesture; not a visual WYSIWYG editor
Graph rules & governance
Solid
stzGraphRule and stzOrgRule feed the one CI gate (stzRuleReport): no-orphan-position, separation-of-duties; the rule catalogue is smallstzGraphRule / stzOrgRule / stzRuleReport
Export & interchange
Solid
stzGraph exports DOT, JSON, GraphML and YAML (Dot(), RenditionAs); import parity thinner, GEXF/adjacency round-trips not all presentstzGraph
Text & label placement
Solid
Notation-in-a-label (DN10), labels centred on cap-height not the em-box (DN12), curve clearance (DN13), solver-placed labels (SolveLabelsAfter)DN10 / DN12 / DN13
General graph layout & edge routing
Partial
Diagram layouts are engine-native; arbitrary large-graph visualization still leans on the optional dot.exe viewer: spline routing, nested clusters unmet
Graph generators & isomorphism
Partial
No standard graph generators (Erdos-Renyi, Barabasi-Albert, Watts-Strogatz) and no isomorphism / graph-edit-distance surfaced
Live / web interactivity
Partial
Diagrams emit interactive SVG and support programmatic re-layout (Relayout, DragTo); no built-in live pan/zoom/brush, the GUI plane's job
