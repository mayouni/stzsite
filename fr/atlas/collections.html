Collections et objets

Un pipeline fonctionnel porté par le moteur et une racine d'objet réflexive ; le stockage boxé plafonne la vitesse des opérations d'ensembles.

6 S5 So1 P

Mesuré contre: Lodash · Immutable.js · standard libraries · Dossiers: base/list · base/object · La page d'origine de l'Atlas

One of the largest surfaces in the library: ~155 list operations in a 6,500-line Zig core behind a 1,600-method Haro face, a functional pipeline, deep-path search, Lodash-grade grouping, and a reflective object root that 449 classes inherit, tuned for millions of items with measured residency wins. Two honest limits keep it short of the very top: boxed value storage holds raw set-op throughput an order of magnitude below NumPy/native, and there are no persistent immutable structures.

Ce qu'un maker en fait, et ce qui se distingue

  • String-expression predicates run inside the engine, which the peers cannot do
  • A deep-path search API that Lodash get only approximates
  • A reflective object root 449 classes inherit, with Q-elevation and the Verb/Verbed/VerbQ grammar
  • Measured residency wins at 1M items: 2.6x read-reuse, Classify -51%, Union -34%

Ce qui est dû

  • Finish the list narration / fidelity grind (312 of ~602 legacy blocks error)
  • Unboxed typed storage for native-speed set-ops
  • Complete the residency migration (Slices 4 and 5, ~32 marshal-in sites)
  • Persistent immutable collections with structural sharing

Core list operations
Strong
Index, slice, section, insert, remove, reverse, swap, rotate, repeat; reads engine-backed (stz_list_get/slice/reverse/rotate); mutators hop through Harostz_list_get / slice / reverse / rotate
Functional pipeline (map, filter, reduce)
Strong
Engine-backed map_expr/filter_expr/reduce_expr with a string DSL (@item, @accumulator) plus W (engine) and WF (Haro function) predicate modesmap_expr / filter_expr / reduce_expr
Search, find, contains, deep paths
Strong
Finder family engine-backed (find_cs, find_all_cs, find_nth_cs, contains_cs) plus a deep-path API (deep_find, item_at_path, paths_at_depth)find_cs / deep_find / find_all_held_cs
Set operations
Solid
Union, intersection, difference, subset, unique engine-backed with a splitmix64 fast path; intersection_cs dedups, common_items_cs keeps dups; 1M union ~2-3sstz_list_union_cs
Grouping, partition, chunk, zip
Strong
classify_cs, partition, chunked, zip, interleave, sliding_window, frequencies_cs engine-backed; classify emits the nested shape engine-side (-51% at 1M)classify_cs (-51% at 1M)
Sorting and ordering
Strong
sort, sort_cs, sort_descending, sort_by_expr, sort_on, sorted_insert plus is_sorted / is_strictly_increasing / is_monotonic, all engine-backedsort_by_expr / sort_on
Aggregation and statistics on lists
Solid
sum, product, mean, median, variance, stddev, nth_largest, ranked engine-backed, also on stzListOfNumbers; deep statistics lives on the Statistics page
Immutability and copy semantics
Partial
Haro assigns lists by value (safe by default, clean Copy()) but no persistent immutable structures with structural sharing; a modified copy is a full copy
Large-scale performance and residency
Solid
