Fichiers et formats

La sûreté d'abord : XXE fermé par construction ; des sous-ensembles délibérés (HTML plat, zip seul, UTF-8, plafond de 64 Mo).

Où il en est

La lecture du Compas Softanza : chaque couloir du domaine noté face au meilleur de sa catégorie, d'après ce que les gardes prouvent (Read from the source on 2026-09-16, from a read-only main worktree). Les phrases du Compas sont en anglais, telles qu'il les a écrites.

A competent, safety-first formats module — engine-backed file I/O, directories (with the Windows non-ASCII listing bug defeated), CSV, JSON, and a namespace-aware XML parser — whose one genuine standout is XML security: XXE is closed by construction, the parser refusing &lt;!DOCTYPE&gt; and &lt;!ENTITY&gt; outright, which lxml and most XML libraries get wrong by default. Everything else is a deliberate subset: XML has no XPath/XSLT/validation (the price of that refusal), HTML is a pragmatic flat index with three selectors (not an lxml DOM), archives are zip-only via Haro's minizip (no tar/gzip vs libarchive), there is no charset detection (UTF-8 only), and reads are whole-file with a 64 MB cap.

The honesty line on the ratings. Re-surveyed from main. The seam fixes are verified in code and guards: XXE refusal (a file:/// entity doc returns FALSE, the SAML fixture still parses), HTML double-decode (&amp;amp;lt; survives), dir non-ASCII (Arabic/CJK filenames, listed count == engine count), and CSV/JSON non-ASCII survival end-to-end. The one live wart is real: the JSON UTF-8 fix exists but the stzJson class constructor isn't migrated to it. Note the test/xml, test/archive and test/zip directories are empty — XML/zip coverage lives under test/file and test/html. UTF-8-only and zip-only are deliberate boundaries.

The one-sentence position. Softanza's formats module chooses correctness and safety over coverage — a parser that refuses XXE by construction, a directory lister that survives non-ASCII names, profiled CSV/JSON with their traps fixed — and pays for it in breadth: no XPath, a flat HTML index, zip-only archives, UTF-8 only, and no streaming past a 64 MB read.

Ce qu'un artisan en fait, et ce qui se distingue

  • XXE closed by construction: the parser refuses <!DOCTYPE> and <!ENTITY>, a posture lxml defaults to wrong
  • The Windows non-ASCII directory listing bug defeated (wide-W API to UTF-8)
  • One strict namespace-aware XML parser shared with XML digital signatures (SAML), with exclusive C14N
  • CSV eval() on list-looking cells removed; byte-scan number test ~156x faster than regex-per-cell

Ce qui est dû

  • Migrate the stzJson constructor to the fixed UTF-8 parser (shipped but unwired)
  • Streaming and large-file reads past the 64 MB cap; iterparse-style XML/JSON
  • A real archive layer (tar, gzip/zlib); charset detection and non-UTF-8 decoding
  • Multiline CSV, richer HTML (slice 3), XPath, a pathlib-style path surface

Repensé depuis les premiers principes

Ce que Softanza a gardé de ce qui marche, et ce qu'elle a repensé, tel que la bibliothèque l'a écrit dans ses documents de conception et ses narrations.

La manière SoftanzaOn aborde un fichier selon ce qu'on veut en faire, et chaque format est analysé une seule fois, dans le moteur, par un analyseur dont les refus font partie de la sécurité.

Gardé des meilleures pratiques

  • La forme canonique XML est comparée octet par octet à libxml2 sur dix vecteurs, gardés comme tests permanents. Une référence indépendante juge le code, pas sa propre parole. source(s'ouvre dans un nouvel onglet)
  • La lecture rend la valeur, pas le texte brut : &amp; revient en &. L'appelant ne décode jamais à la main, donc rien n'est affiché brut ni échappé deux fois. source(s'ouvre dans un nouvel onglet)
  • Une classe par format, pas par source. JSON, CSV, HTML et XML prennent du texte ; un fichier est une source, pas un genre, et charger ou enregistrer reste une commodité. source(s'ouvre dans un nouvel onglet)

Repensé

  • Un fichier s'ouvre par intention, pas par mode : FileRead, FileAppend, FileCreate, FileOverwrite, FileUpdate. Chaque intention permet aussi de lire, comme un cahier ouvert. source(s'ouvre dans un nouvel onglet)
  • L'analyseur XML refuse toute déclaration DOCTYPE ou ENTITY avant d'analyser. La lecture de fichiers piégée et l'explosion mémoire sont exclues par construction, pas par un réglage oubliable. source(s'ouvre dans un nouvel onglet)
  • Les chemins XML n'ont que trois formes, et comparent les noms locaux. Un XPath partiel inviterait des requêtes qui échouent en silence ; un préfixe n'est qu'un surnom local. source(s'ouvre dans un nouvel onglet)
  • Une clé de stockage d'objets n'est pas un chemin. Chaque fichier porte le SHA-256 de sa clé : la traversée de chemin devient inexprimable et Photo.JPG reste distinct de photo.jpg. source(s'ouvre dans un nouvel onglet)

12 couloirs, chacun face au meilleur de sa catégorie

Pour chaque couloir : ce qui tourne dans le moteur aujourd'hui, les outils contre lesquels il est juste de le mesurer, et ce qui reste dû.

01XML security — XXE closed by constructionStrong

In the engine

xml.zig refuses any document containing &lt;!DOCTYPE&gt; or &lt;!ENTITY&gt; — a hard failure, not sanitization — so external-entity injection is unrepresentable. Guarded: a file:///etc/passwd entity doc returns FALSE; ordinary and SAML-signed docs parse.

Measured against

lxml (needs defusedxml)defusedxmlmost XML libs

To complete

The XXE footgun that has burned lxml, Java and .NET users is closed at the parser, by refusal — a security posture the category leaders default to wrong. The cost is paid honestly in the query lanes below.

02File I/OSolid

In the engine

file.zig: read / write / append / copy / delete / stat (size, mtime), engine-backed, with a pathIsUsable screen that catches Windows-illegal characters before Zig std would crash the host DLL. Bytes and text; UTF-8 paths.

Measured against

Go os / ioRust std::fsPython open

To complete

64 MB read cap (larger files return empty), no streaming/chunked reads, no mmap/seek, and Move is copy+delete (no engine rename). Solid for ordinary files, not for large or streamed ones (lane 12).

03Directory operationsSolid

In the engine

list / walk / create / delete / count via stz_dir_*, and the non-ASCII listing bug fixed: Haro's native dir() routes through the Windows ANSI code page (Arabic + CJK names both collapse to &quot;??.txt&quot;); the engine uses the wide-W API → UTF-8, so names survive.

Measured against

Go filepath.WalkPython os / pathlib

To complete

A real correctness win (guarded: listed count == engine count over Arabic/CJK/Hebrew/emoji filenames). Deep walking is Haro-side; no parallel walk.

04CSVSolid

In the engine

csv.zig: RFC-4180 quoting (&quot;&quot; escaping), configurable separator, header auto-detection, exact-round-trip type inference (&quot;007&quot; preserved). Two seam fixes: removed eval() on list-looking cells (arbitrary code from data), and a byte-scan number test ~156× faster than the old regex-per-cell.

Measured against

Python csvpandas read_csv

To complete

No multiline quoted fields — rows are split on newlines before field parsing, so a newline inside a quoted cell breaks the row; and a multi-byte separator falls back to a Haro split with no quote handling.

05JSONSolid

In the engine

json.zig (std.json) parse / serialize / pretty, and the UTF-8 trap fixed in StzJsonToList — Haro's own JsonToList loses its place on a raw multibyte byte and never reads \uXXXX; the engine parser does both. Plus a big-file JsonFilterFeatures escape hatch (GeoJSON, in-engine).

Measured against

Python jsonjqserde_json

To complete

The wart: the fix exists and the flat StzJson* helpers use it, but the stzJson class constructor still calls the old broken pure-Haro parser. Also no JSONPath, no streaming.

06XML parsing & querySolid

In the engine

A strict, namespace-aware single parser (xml.zig) shared with XML digital signatures (xmldsig.zig/SAML), with exclusive C14N canonicalization and a small local-name path grammar (Root/Child/Leaf, //Leaf, Item[2]). Builder escapes every value.

Measured against

lxml (XPath 1.0 + XSLT + validation)ElementTree

To complete

No XPath, XSLT, or DTD/XSD validation — the deliberate price of the XXE refusal. A safe, namespace-aware subset that carries real SAML, not a full lxml.

07File watchingSolid

In the engine

fswatch.zig — a cross-platform worker that snapshots (mtime, size) and diffs to ADD / MOD / DEL events; stzFolderWatcher.Watch / Drain / Stop.

Measured against

inotify / FSEventswatchdogchokidar

To complete

Polling-based — no native OS events (inotify/FSEvents/IOCP) — so it trades latency and scale for portability. Correct, but not event-driven.

08HTML parsing & queryPartial

In the engine

html_dom.zig — a pragmatic tokenizer + flat element index (depth recorded, not a nested tree), with tag / #id / .class selectors, entity encode/decode (the double-decode fix: &amp;amp;lt; survives), and the O(n²) Find fix (all class matches in one pass).

Measured against

lxml.htmlBeautifulSoupcheerio

To complete

Self-declared "not a spec-compliant HTML5 parser": no real DOM tree, no descendant/child combinators, no mutation, read-only. The full CSS selector + DOM builder is deferred ("slice 3").

09Archives & compressionPartial

In the engine

stzZipFile does zip read and write (create from file/dir, add, extract, list, contains) — but backed by Haro's native ziplib (minizip), not the Softanza engine. The engine compressor.zig offers only crc32 / adler32 / RLE / a bespoke codec.

Measured against

libarchive (tar/zip/7z/xz/zstd)Python zipfile/tarfile

To complete

Zip only. No tar, no gzip/zlib as a user format, no 7z, no streaming filters — the many-format, streaming breadth libarchive is built on is absent, and even zip isn't engine-backed.

10Path manipulationPartial

In the engine

Engine stz_path_extension / basename / dirname (handle both / and \).

Measured against

Python pathlibGo path/filepath

To complete

Three primitives only — no join / normalize / relative-to / glob and no pathlib-style path object. Enough to split a path, not to manipulate one.

11Streaming & large filesPartial

In the engine

Whole-file read only, with a hard 64 MB cap; the one large-file path is the domain-specific JsonFilterFeatures (GeoJSON matched in-engine so a 40 MB file never crosses the bridge).

Measured against

stdlib streaming readerslxml iterparsemmap

To complete

No streaming or chunked reads, no iterparse, no mmap / random-access. A file larger than the cap simply doesn't load — the biggest structural limit of the plane.

12Encoding / charsetEmerging

In the engine

None for text: codec.zig is Base64 only, and everything is UTF-8 by design (stated across file.zig, xml.zig).

Measured against

chardeticonvlxml encoding detection

To complete

No charset detection and no non-UTF-8 decoding — so a Windows-1252 CSV, a Shift-JIS document or a legacy-encoded HTML page can't be read correctly. The wild is not all UTF-8.

Ce qui est dû, dans l'ordre du rendement

Les manques, classés par ce qu'ils rapportent et non par leur taille ; la valeur est l'effet sur la portée de la bibliothèque, l'effort une lecture d'ingénieur.

Tier A — the shipped-but-unwired fix & the size wall

Migrate the stzJson constructor to the fixed parser

The UTF-8 fix (StzJsonToList) already exists and the flat helpers use it — but the stzJson object constructor still calls the old pure-Haro parser that drops multibyte bytes and ignores \uXXXX. Point the ctor at the fix. Low effort, closes a silent-corruption path on the main surface.

Valeur · élevéeEffort · faible
Streaming & large-file reads

Chunked/streaming file reads past the 64 MB cap, plus iterparse-style incremental XML/JSON. Today a file larger than the cap simply returns empty — the plane's biggest structural limit.

Valeur · élevéeEffort · moyen

Tier B — formats & encodings

A real archive layer

Engine-backed tar and gzip/zlib alongside zip (toward libarchive's format breadth and streaming filters) — so the archive lane is more than Haro's minizip and covers the formats data actually arrives in.

Valeur · moyenneEffort · moyen
Charset detection & non-UTF-8 decoding

Detect and decode Windows-125x, Shift-JIS, ISO-8859-* (shared with the String page's legacy-charset gap), so files and pages not born in UTF-8 read correctly instead of mangling.

Valeur · moyenneEffort · moyen
Multiline CSV + richer HTML

Parse fields before splitting rows (fixing newlines-in-quoted-cells), and land HTML "slice 3" — full CSS selectors, a real DOM, and mutation — lifting HTML from a flat read-only index.

Valeur · moyenneEffort · moyen

Tier C — query & path depth

XPath (or a richer query) for XML/HTML

A real query language over the safe parser — XPath is orthogonal to the XXE refusal, so it can be added without reopening the security hole. Closes the biggest lxml gap.

Valeur · moyenneEffort · élevé
A pathlib-style path surface

join / normalize / relative-to / glob and a path object — beyond the three split primitives — so path manipulation is first-class, not hand-assembled.

Valeur · moyenneEffort · faible
mmap, engine rename & format sniffing

Random-access via mmap, a real engine rename (today Move is copy+delete), and magic-byte/MIME format detection beyond the current text heuristics.

Valeur · faibleEffort · moyen
