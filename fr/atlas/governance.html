Doctrine de gouvernance

La signature : un modèle ne peut pas agir par construction ; répéter puis commettre, une seule porte de règles sur onze domaines, la production refuse les faux.

5 Strong 5 Solid 2 Partial

Mesuré contre : OPA · Deno · Vault · Dossiers : base/agentic(s'ouvre dans un nouvel onglet) · base/system(s'ouvre dans un nouvel onglet) · base/security(s'ouvre dans un nouvel onglet) · base/service(s'ouvre dans un nouvel onglet) · base/graph(s'ouvre dans un nouvel onglet) · Pour les programmeurs : la référence de ce domaine

N'essayez pas de construire des agents sûrs ; construisez un monde sûr et laissez des agents ordinaires y travailler. C'est la signature de Softanza, la seule capacité où, mesurée face à .NET, Python, Wolfram et la JVM, elle couvre un terrain qu'aucun d'eux ne couvre.

La sûreté est architecturale, non procédurale. Un acteur modèle de langage détient la capacité inference et rien d'autre ; lui accorder effectful lève une erreur à la construction, dans le graphe des agents et, mot pour mot, dans un fichier d'agent .pia. Le travail à effets se répète dans un monde virtuel qui ne tient aucune référence à la réalité, et l'unique sortie d'un cycle est un plan de mise à jour que l'on peut relire et rejeter ; exécuter le plan fait passer chaque opération par trois portes, relecteur, périmètre de commit, capacité, et le plan peut dire, avant toute tentative, que le plan de ce modèle ne peut pas franchir. Un humain peut commettre exactement le même plan. La permission n'est pas l'autorité : un agent peut détenir le droit à une action et être refusé quand même, parce que son rang ne couvre pas le risque de l'action, et la réponse explique pourquoi. Risque et réversibilité sont deux axes séparés ; du code écrit par un modèle ne peut faire que du travail réversible.

Une seule porte de règles juge ensuite le résultat sur onze domaines, code, sécurité, agents, organisations, services, modèles de diagrammes, sous une seule forme de constat. Les secrets s'expurgent d'eux-mêmes et ne se révèlent qu'à un acteur à effets hors bac à sable ; le registre d'audit est chaîné par hachage dans le moteur ; la production refuse un bac à sable encore lié, par construction. Et le domaine va dans l'autre sens : le gestionnaire de sécurité de Java est déprécié, la sécurité d'accès au code de .NET a été retirée. Softanza intègre ce que les plateformes retirent.

Les trous honnêtes sont nommés par la doctrine elle-même : les sortes de capacités sont des chaînes, donc il n'y a pas de type formel qu'on ne puisse contourner autour de l'octroi ; la porte d'enregistrement n'est pas encore le défaut ; et la conversation sur un plan, un agent recevant des objections et révisant, est conçue et non bâtie. Cinq couloirs Strong, cinq Solid ; les dus sont le type étanche derrière la discipline et la boucle de négociation.

Où il en est

This is Softanza's signature — the one capability where, in the platform survey, it out-covers .NET, Python, Wolfram and the JVM alike. The doctrine is that safety is architectural, not procedural: an LLM (or any untrusted capability) cannot act effectfully by construction — it holds only the inference capability, granting it effectful raises at construction, and effectful work rehearses in a semantic virtual world whose only export is a reviewable update plan a governed actor commits. One rule gate then judges the result across eleven domains. And the field is moving the other way — Java's SecurityManager is deprecated, .NET's Code Access Security was removed — so Softanza builds in what the platforms are retiring.

"We will not build safe agents. We will build a safe world, and let ordinary agents loose inside it. The workbench holds no reference to reality."

The honesty line on the ratings. This page rates a cross-cutting doctrine, not a module — it lives across base/agentic, base/system, base/security, base/service and base/graph. Read from main. The strengths are real and guarded: Grant refuses at construction; the safe-world twin exports a reviewable plan; MayCommit refuses the LLM before it tries; the 11-domain rule gate; production refuses fakes; the hash-chained ledger; capability-gated secrets. The weaknesses are equally on the page, and the design doc grades itself this candidly (SOFTANZA_INTELLIGENCE_ARCHITECTURE.md §3.1–3.2): the negotiation loop and stzHybridAgent are design-only, the registration gate is opt-in, and there is no formal capability type — the audit is where "by construction" becomes "by detection."

The one-sentence position. Softanza is the only stack in the mainstream field that makes safe execution architectural rather than procedural — the LLM cannot act because it never holds the capability, effectful work rehearses in a reviewable world, and one gate judges the result across every domain; what it still owes is the airtight type behind the discipline and the negotiation loop that lets an agent argue with its own rejected plan.

Ce qu'un artisan en fait, et ce qui se distingue

  • Safety is architectural, not procedural: an LLM cannot act effectfully because it never holds the capability
  • A semantic sandbox whose only export is a reviewable, rejectable update plan, not an opaque container
  • One rule gate judging code, agents, services, security and diagram models across 11 domains
  • Production refuses fakes by construction: sandbox-in-production raises, and the sandboxes are genuine

Ce qui est dû

  • A formal capability type that cannot be forged around Grant
  • Flip the engine-loop registration gate (MayRegister) to default
  • Close the host-function escape with a behavioural check, and wire the native agent roster
  • The negotiation loop (Receive/Revise), the evaluation hall and branches, and stzHybridAgent

Ce que Softanza a gardé de ce qui marche, et ce qu'elle a repensé, tel que la bibliothèque l'a écrit dans ses documents de conception et ses narrations.

Gardé des meilleures pratiques

  • Séparation des pouvoirs : qui imagine un changement n'est pas qui l'exécute. Les plans proposés sont exécutés par des acteurs habilités, dans un périmètre déclaré et avec une trace d'audit. source(s'ouvre dans un nouvel onglet)
  • Refus par défaut : une action sans niveau de risque déclaré ne s'exécute jamais. L'échec habituel, un agent qui fait ce que personne n'a pensé à interdire, devient impossible. source(s'ouvre dans un nouvel onglet)
  • Chaque décision reste traçable : qui a décidé quoi, quand, avec quelle autorité et quel risque. La trace survit à l'enregistrement et se consulte par acteur, action ou période. source(s'ouvre dans un nouvel onglet)

Repensé

  • Un agent travaille sur un établi virtuel : il croit avoir écrit le fichier, mais le disque n'a pas bougé. Seul un plan sort, validé par un autre acteur. source(s'ouvre dans un nouvel onglet)
  • Un agent est un fichier jugé au chargement, seul moment où la réponse ne coûte rien. S'il ne déclare ni sa portée ni sa réversibilité, il est refusé. source(s'ouvre dans un nouvel onglet)
  • La permission n'est pas l'autorité. Un agent peut avoir le droit de faire une action et être refusé quand même, car son niveau d'autorité ne couvre pas le risque. source(s'ouvre dans un nouvel onglet)
  • Risque et réversibilité sont deux axes : plus un acte est difficile à défaire, plus son code doit être fiable ; un code écrit par un modèle ne fait que du réversible. source(s'ouvre dans un nouvel onglet)

La manière Softanza, exécutée

Ce que Softanza fait autrement dans ce domaine, montré par du code tiré de ses narrations et de ses gardes, et exécuté pour cette page.

Un agent qui ne dit pas ce qu'il couvre, ou à quel point son travail est réversible, ne peut pas s'inscrire, et chaque refus nomme sa règle.

? "no coverage stated -> " + oGov.MayRegister("mystery", "", "reversible")

12 couloirs, chacun face au meilleur de sa catégorie

Pour chaque couloir : ce qui tourne dans le moteur aujourd'hui, les outils contre lesquels il est juste de le mesurer, et ce qui reste dû.

01Propose-don't-act, by constructionStrong

In the engine

stzAgentGraph gives every actor a capability set and a taint colour. AddLLMActor grants [&quot;inference&quot;] only — the effect set is empty — and Grant(llm,&quot;effectful&quot;) raises: "an LLM proposes, only a pi-gate commits — enforced at CONSTRUCTION, not merely audited."

Measured against

OPA / RegoNeMo GuardrailsLangChain tool sandboxes

To complete

The refusal is structural, not a runtime policy check. The effect capability simply isn't in the LLM actor's set to begin with — closer to object-capability discipline than to a prompt-level or stack-walk guard. Guard: agentgraph_narrated.

02The safe world — rehearse → plan → commitStrong

In the engine

stzVirtualSystem + stzVirtualFileSystem are a real in-memory twin (tree state, snapshots, branches, tombstones). Effectful work runs against the twin; the tick's only export is a reviewable stzUpdatePlan. Principle P1: "the virtual layer holds no reference to reality."

Measured against

gVisor / seccompDeno permissionsVM sandboxes

To complete

Unlike a container you can only throw away, the plan is a reviewable, rejectable artifact — a semantic sandbox that speaks files and operations, not opaque syscalls. Guard: safeworld_narrated (76/76).

03The single crossing & capability latticeStrong

In the engine

stzUpdatePlan.Execute() passes every operation through three gates — reviewer, commit scope (stzCommitScope), and capability (executor.Can(RequiredKind())). MayCommit() answers "this LLM's plan cannot cross" before any attempt; the lattice (effectful/sensing/compute/inference) refuses an unknown kind.

Measured against

object-capability systemsWASI capabilities

To complete

The gates compose — an LLM is refused even inside an allowing scope, and a human can commit the very same plan. One crossing point between imagination and reality. Guard: governance_crossing_narrated (Scene 10).

04The unified rule gateStrong

In the engine

stzRuleReport collects findings in one shape [:rule,:subject,:where,:severity,:message] with IsSound(), from 11 self-checking domains (code, security, agent, org, service, ER, petri, network, fault, family, diagram); stzPredicateSet is the signable, sha256-sealed constitution.

Measured against

OPASonarQubesemgrep

To complete

One gate spanning code and agents and services and security and diagram models — broader than any single policy engine's remit (each is single-domain). The governance verdict has one address.

05Governed effects in system programmingSolid

In the engine

OS effects — create_file, set_var, spawn_process, change_dir — are stzVirtualOperations requiring the effectful capability; they reach reality only through the update plan, which refuses any executor lacking the kind or a declared trust posture. stzVirtualEnvironment extends the twin to env vars and cwd.

Measured against

Go / Rust std (ungoverned)capability OSes

To complete

The doctrine applied to the OS surface — real and guarded (governance_crossing, env twin) — but a focused effect set (files / env / process), not yet the whole syscall surface.

06Capability-gated secretsSolid

In the engine

stzSecretStore is enumerable and all reads self-redact; Reveal(name, actor) is gated to an effectful, non-sandboxed actor, so an inference-only LLM cannot reveal a secret. Refusals are recorded as security events — the secret name only, never the value. stzVaultResolver bridges external stores.

Measured against

HashiCorp Vaultcloud secret managers

To complete

The secret gate is the same lattice as the effect gate — one capability model, not a bolt-on keyring. Vault-grade discipline built into the doctrine. Guard: secretstore_narrated.

07Tamper-evident ledgerSolid

In the engine

stzSecurityLedger is append-only and hash-chained (Verify() names the first broken link); SealTo(path,key) is a keyed HMAC-SHA256 export, and a Haro copy records into the same evidence. It is honest about its threat model: it detects retroactive edits, but an in-process attacker can still append or wipe.

Measured against

Vault audit devicestransparency logs

To complete

Tamper-evidence with a stated, honest threat model — strong on retroactive edits, explicit that it is not append-proof against an in-process attacker. Guard: security_ledger_narrated (10 scenes).

08Production refuses fakesStrong

In the engine

stzServiceRegistry asks each service its posture — :sandbox (a fake, must-not-ship), :local, :live. SetPhase(:production) raises an ERROR sandbox-in-production and ephemeral-in-production (a sqlite &quot;:memory:&quot; — one character from the safe spelling); stzServiceRule answers, in development, which part depends on a fake.

Measured against

WireMockTestcontainersservice virtualization

To complete

A fake reaching production is refused by construction, not by discipline — and the sandboxes are genuine (a real P-256 key), so "we tested against the sandbox" means something. Guard: service_registry_narrated.

09Identity, posture & responseSolid

In the engine

A broad shipped surface (23 files in base/security): auth (stzAuth, OIDC, SAML, passkey, TOTP, request signer) plus stzSecurityPosture / Attestation / Drill / Sentinel / Detection / Incident / ResponsePlan, with stzSecurityGraph self-checking via CheckRules() into the same rule gate.

Measured against

KeycloakAuth0SPIFFE

To complete

A comprehensive identity + posture layer feeding the one gate — broad and real, though it composes existing protocols (OIDC/SAML/passkey) rather than inventing them. The doctrine's perimeter, not its novelty.

10Governance as a file — the `.pia` agentSolid

In the engine

stzAgentDeclaration compiles a .pia declarative agent to the same classes and quotes stzAgentGraph.Grant's refusal verbatim — "one rule, two doors, same words." A pia: 2 posture requirement refuses a ring: clause with no declared posture. An agent is a file judged at load.

Measured against

policy-as-code (Rego files)agent manifests

To complete

The doctrine reachable declaratively, not only in code — a distinctive "constitution as a file." The v1 files remain readable as a stated migration debt (lane 12).

11The negotiation & evaluation loopPartial

In the engine

The plan now reaches the agent (stzAgentWorkbench + GiveWorkbench, shipped 2026-08-22), but the conversation about the plan is design-only: Receive(issues) / Revise(), stzAgentEvaluation (the "examination hall"), and branch-per-hypothesis (BranchFrom / CompareBranches exist on the vfs but no agent uses them).

Measured against

critique/revise agent loopsreflection frameworks

To complete

The doc's own words: "the plan reaches the agent; the conversation about the plan does not yet." Build Receive/Revise, the evaluation hall, and branch-per-hypothesis into a real agent. stzHybridAgent is named but never built as a class.

12Airtight-by-construction (closure)Partial

In the engine

The by-construction guarantees are real at the Grant boundary and the plan crossing; where they aren't, an audit (Violations()) is the acknowledged backstop — "by construction" becoming "by detection" at the edges.

Measured against

object-capability type systemsformal capability models

To complete

Three honest holes: no formal capability type (kinds are strings in list properties, and a raw SetNodeProperty bypasses Grant); the registration gate is opt-in (a migration default until the last in-tree host declares); the ring: escape checks the function name, not what it does (backstopped by posture + reversibility, not closed).

Ce qui est dû, dans l'ordre du rendement

Les manques, classés par ce qu'ils rapportent et non par leur taille ; la valeur est l'effet sur la portée de la bibliothèque, l'effort une lecture d'ingénieur.

Tier A — make the guarantee airtight

A formal capability type

Capabilities are string kinds in list properties, so a raw SetNodeProperty can still grant an effect around Grant — the Violations() audit catches it after the fact. A real capability type that cannot be forged would turn the last "by detection" edges into "by construction."

Valeur · élevéeEffort · moyen
Flip the registration gate to default

The engine-loop registration gate (MayRegister) is opt-in (UseEngineLoop()); the default only flips when the last in-tree host declares. Wire appserver/, cluster/ and perf/ to declare, and the migration state becomes the guarantee.

Valeur · élevéeEffort · moyen

Tier B — finish the wiring

Close the ring: escape

The ring: clause is checked by function name, not by what the function does — closed today only by the pia: 2 posture requirement composed against reversibility. Make the check behavioral (or run the body itself in the twin) so a mislabeled function can't slip an effect through.

Valeur · moyenneEffort · moyen
Wire the native roster

stzOwnAgentStack declares five library-internal agents and wires one (wise-coder); the other four raise if asked. Finishing them turns the "self-governing library" from a demonstrated pattern into a live one.

Valeur · moyenneEffort · faible

Tier C — build the conversation about the plan

The negotiation loop

Ship Receive(issues) / Revise() so a rejected plan comes back to the agent with the reviewer's findings, and the agent proposes again — the missing half of propose-review-commit. The plan reaches the agent; the argument about it should too.

Valeur · moyenneEffort · élevé
The evaluation hall & branches

Wire stzAgentEvaluation and branch-per-hypothesis (the vfs already has BranchFrom / CompareBranches) so an agent can rehearse several plans and a governed actor picks the winner — rehearsal as comparison, not just as a single dry run.

Valeur · moyenneEffort · élevé
Build stzHybridAgent

AddHybridActor is only a graph node and colour — a composition proven sound that instantiates nothing. Building it as a real class would let one actor hold both proposing and (scoped) committing roles under the same lattice.

Valeur · faibleEffort · moyen
