Palier neuronal

Un vrai moteur d'inférence, vérifié contre numpy (BERT et LLM, décodage contraint) ; l'entraînement et la fonderie sont dus.

4 Strong 4 Solid 3 Partial 1 Emerging

Mesuré contre : ggml/llama.cpp · ONNX Runtime · Dossiers : base/neural(s'ouvre dans un nouvel onglet) · Pour les programmeurs : la référence de ce domaine

Un modèle neuronal, dans Softanza, est un fichier GGUF standard que la bibliothèque exécute sur son propre ggml embarqué, et chaque capacité qui en use marche aussi sans aucun modèle : elle s'affine quand un modèle local est présent, et ne dépend jamais de quoi que ce soit de payant ou de distant.

Le côté consommation est réel et vérifié. La famille BERT tourne de bout en bout, plongements, états de jetons, reconnaissance d'entités, reclassement, et coïncide avec une implémentation numpy indépendante du même passage avant à 1,64e-7 près. Les découpeurs en jetons sont exacts à l'identifiant. Un décodeur causal exécute llama, qwen et smollm avec cache clé-valeur, flux et plusieurs tours. La voie GPU s'enclenche quand un étalonnage mesuré dit qu'elle gagne, et retombe sur la réponse CPU sinon.

L'idée propre à Softanza est que la structure tue les réponses malformées, jamais les fausses. Un stzOutputSchema déclaré se compile en grammaire imposée à l'échantillonneur, si bien qu'un jeton invalide ne peut même pas être émis ; puis un tribunal vérifie les valeurs, ce qu'aucune grammaire ne peut faire. stzLLMFunction fait d'un appel au modèle une fonction typée pure : un type déclaré ou un refus, un budget obligatoire, aucun pouvoir d'agir. La garde qui prouve la limite est gardée à dessein : un mensonge bien formé sur l'âge d'Ada Lovelace est validé, parce qu'un schéma garantit la forme et non la vérité.

oS = StzOutputSchemaQ([
    [ :field = "name", :type = :string ],
    [ :field = "age",  :type = :number,
      :must = [ [ ">=", 0 ], [ "<=", 130 ] ] ],
    [ :field = "mood", :type = :oneof,
      :choices = [ "positive", "negative" ] ]
])

# an answer wrapped in prose is read as the structure it holds
cAnswer = 'Sure: { "name": "Ada", "age": "36", "mood": "POSITIVE" }'
aV = oS.ParseOutput(cAnswer)

? aV[:ok]
#--> TRUE

# and a representable scalar arrives as what was declared
? aV[:value][:age] + 1
#--> 37

# prose that is not a structure is refused, not scavenged
? oS.ParseOutput("I would rather not say.")[:ok]
#--> FALSE

Ce qui manque, c'est le côté production, et la page le dit : pas d'entraînement de transformeur (la passe arrière de ggml est embarquée mais éteinte), pas de quantification d'un modèle, pas d'ONNX. Quatre couloirs sont notés Strong, quatre Solid ; un exécuteur de la classe de llama.cpp câblé dans une bibliothèque gouvernée, pas encore une usine à modèles.

Où il en est

La lecture du Compas Softanza : chaque couloir du domaine noté face au meilleur de sa catégorie, d'après ce que les gardes prouvent (Read from the source on 2026-09-16). Les phrases du Compas sont en anglais, telles qu'il les a écrites.

The docs and the code disagreed; the code wins. The consumption side is complete and genuinely wired to a patched, vendored ggml: real GGUF loading, id-exact WordPiece/BPE tokenizers, a numpy-parity BERT encoder (embeddings, NER, rerank), a multi-architecture causal LLM decoder (llama / qwen / smollm) with KV-cache and grammar-constrained decoding, and a measurement-gated wgpu GPU path. What is not there is the production side: training runs only for small pure-Zig MLPs, ggml's own backward pass is vendored-but-dark, quantization is consume-only, and there is no ONNX. A llama.cpp-class runner, wired into a governed library — not yet a training or model-production platform.

The honesty line on the ratings — and a docs correction. The design doc is stale: it still says "no ggml bridge" and "cannot yet write GGUF," both contradicted by shipped, committed code (neural_matmul.zig, gguf_export.zig, "R4 CLOSES"). Project memory's "Neural tier COMPLETE, numpy parity" is true for inference and would overclaim if read as the full training vision. This page rates the code, not either doc. And the numpy-parity (1.64e-7) covers the BERT forward + core numerics only — not the pure-Zig trainer and not the LLM decoder, which has no committed CI model and is proven by construction with graceful skips.

The one-sentence position. Softanza's neural tier is a real, numpy-verified, governed inference engine — GGUF in, embeddings / NER / rerank / grammar-constrained generation out, on CPU or measured GPU — that stands with the local-inference field on consumption, and is a full program away from it on production: training a transformer, quantizing it, and writing it back out.

Ce qu'un artisan en fait, et ce qui se distingue

  • numpy-parity BERT encoder (1.64e-7)
  • grammar-constrained decoding wired to the structured-output contract
  • id-exact WordPiece and BPE tokenizers
  • measurement-gated wgpu GPU path (2-5x)

Ce qui est dû

  • wire ggml's backward pass -- the training foundry
  • a quantization (encode) path
  • ship or fetch a real semantic model for CI
  • ONNX import

Repensé depuis les premiers principes

Ce que Softanza a gardé de ce qui marche, et ce qu'elle a repensé, tel que la bibliothèque l'a écrit dans ses documents de conception et ses narrations.

La manière SoftanzaChaque capacité fonctionne sans aucun modèle, gagne en finesse quand un modèle local est présent, et ne dépend jamais d'un service payant ou distant.

Gardé des meilleures pratiques

  • Les modèles sont des fichiers GGUF standard, exécutés par le moteur ggml intégré. Softanza consomme d'abord le format commun, et n'apprend que plus tard à l'écrire. source(s'ouvre dans un nouvel onglet)
  • Le décodage contraint par une grammaire reprend l'algorithme de l'échantillonneur de llama.cpp, la référence pour GBNF. La machine elle-même est écrite en interne. source(s'ouvre dans un nouvel onglet)
  • L'encodeur de texte est vérifié contre une implémentation numpy indépendante du même calcul, dans une marge de tolérance mesurée. source(s'ouvre dans un nouvel onglet)

Repensé

  • La structure élimine les réponses mal formées, pas les mensonges. Une grammaire façonne la réponse pendant sa génération. Un tribunal vérifie ensuite les valeurs, ce qu'aucune grammaire ne sait faire. source(s'ouvre dans un nouvel onglet)
  • Un appel au modèle est une fonction pure et typée : le type déclaré ou un refus, un budget obligatoire, aucun pouvoir d'agir. Une réponse cassée ne passe jamais pour une valeur. source(s'ouvre dans un nouvel onglet)
  • Un fichier de modèle ne s'ouvre que si son empreinte correspond à une empreinte enregistrée. La vérification précède toute lecture, car c'est l'analyseur qui est exposé aux attaques. source(s'ouvre dans un nouvel onglet)
  • La consigne jointe à une demande structurée est fixée par la mesure. Des conseils supplémentaires ont fait tomber les réponses valides à 0 sur 10, et ont été retirés. source(s'ouvre dans un nouvel onglet)

12 couloirs, chacun face au meilleur de sa catégorie

Pour chaque couloir : ce qui tourne dans le moteur aujourd'hui, les outils contre lesquels il est juste de le mesurer, et ce qui reste dû.

01GGUF model loadingStrong

In the engine

neural_embed.zig loads GGUF metadata + weights into a ggml context — arch-prefixed KV reads, tensor enumeration, F16 / Q8_0 de-quant on load. Exposed as StzEngineNeuralModelLoad / stzNeuralModel.LoadFrom, tested against a committed tiny_bert.gguf.

Measured against

llama.cppggml

To complete

Real GGUF loading at reference parity — the format is read faithfully across encoder and decoder families. Nothing structural owed on load.

02TokenizersStrong

In the engine

Both families, from the GGUF vocab/merges: WordPiece / SentencePiece-metaspace (encoder, auto-detect ## vs ▁, cased detection, special tokens) and GPT-2 byte-level BPE (decoder, ChatML control tokens). Tokenization is id-exact against a numpy reference.

Measured against

llama.cpp tokenizersHF tokenizers

To complete

Id-exact parity for both schemes is exactly what a tokenizer must guarantee. At parity.

03Encoder inference (BERT family)Strong

In the engine

neural_embed.zig runs a full BERT-family forward (MiniLM / BERT / RoBERTa / jina-bert-v2, auto-adapting learned-pos vs ALiBi, standard vs GEGLU FFN): sentence embeddings, token states, NER, and cross-encoder rerank — matching an independent numpy reference to 1.64e-7.

Measured against

ONNX Runtime (BERT)sentence-transformersggml

To complete

Numerically verified against numpy — the strongest correctness proof in the tier. A genuinely complete encoder path.

04Constrained / structured decodingStrong

In the engine

GBNF grammar-constrained decoding (gbnf_machine.zig, schema_gbnf.zig): a schema compiles to a grammar that makes invalid tokens unemittable, wired to stzOutputSchema / structured output. Measured value: ~5 calls per valid answer without the grammar, one with.

Measured against

llama.cpp GBNFoutlinesguidance

To complete

At llama.cpp parity for grammar-constrained decoding, and integrated with the library's structured-output contract — a distinctive strength.

05Decoder inference (causal LLM)Solid

In the engine

neural_gen.zig — llama / qwen2 / qwen3 / smollm: RMSNorm + RoPE + GQA + SwiGLU + KV-cache, tied/untied lm-head, greedy and temp/top-k/top-p sampling, streaming (neural_gen_start/next) and multi-turn.

Measured against

llama.cppollamaMLC / vLLM

To complete

A real, functional decoder — but narrower than llama.cpp (four architectures, no speculative decoding), and CI has no generative model, so it runs only with a user-supplied GGUF and is proven by construction, not by a parity fixture.

06Tensor ops & the numeric bridgeSolid

In the engine

The vendored ggml tensor core is wired and exercised (mul_mat, soft_max_ext, rope_ext, norms, activations), and a stzMatrix↔ggml bridge (neural_matmul.zig, R4 step 2) routes f64 matmul through ggml's threaded SIMD kernel with a resident cache.

Measured against

ggml (full tensor lib)ONNX RuntimePyTorch tensors

To complete

The bridge is matmul-only — no general tensor exposure and no backward pass into the numeric plane. The doc's "ggml available to all numerics" is a seed, not the full graft.

07Semantic index & embeddings pipelineSolid

In the engine

stzSemanticIndex (AddText / Search over StzNeuralEmbeddingOf), the embedding seam the NLP tier gates on, and stzLLMFunction / structured-output faces on top.

Measured against

sentence-transformers + FAISSONNX embeddingsllama.cpp embed

To complete

The pipeline is shipped and tested, but the strong model is user-supplied (only a synthetic 83 KB tiny_bert.gguf is git-tracked), and the index itself is basic next to a tuned ANN store.

08GPU executionSolid

In the engine

Softanza's own wgpu backend (f32): a resident BERT backbone (neural_backbone.zig, WGSL matmul + fused-attention kernels) that now auto-routes to the GPU through a shape-keyed calibration foundry (GK0–GK2c) — measured 2.08× on the backbone forward and 5.3× over the full CPU forward, selecting a persisted winning kernel per shape.

Measured against

llama.cpp (CUDA / Metal / Vulkan)ONNX Runtime (CUDA / DirectML)

To complete

GPU now engages automatically on the inference path when calibration favors it — no longer dormant. But training and quantization see no GPU work, ggml's own mature CUDA/Metal/Vulkan backends are pruned, and coverage is per-shape rather than whole-graph.

09Training & backward passPartial

In the engine

Real training exists — but in the pure-Zig ML floor: nn.zig forward + backward SGD for small dense MLPs (learns XOR and multiclass, tested), plus scalar reverse-mode autodiff.zig for optimization objectives.

Measured against

ggml trainingPyTorchONNX Runtime training

To complete

No transformer training: ggml's own backward pass (ggml-opt.cpp) is vendored but never called. Training a real neural model — the production half — is owed.

10QuantizationPartial

In the engine

Consume-only: F16 and Q8_0 weights are de-quantized on load (dequantRows), so quantized models run correctly.

Measured against

llama.cpp (Q4_K / Q5_K / …)ggml quantizeGPTQ / AWQ

To complete

No encode path — Softanza cannot quantize a model, and GGUF export writes F32 only. The whole k-quant family that makes local LLMs deployable is absent.

11GGUF export & the foundryPartial

In the engine

gguf_export.zig — "Softanza writes the format it reads": exports GGUF for small F32 nets (the stz-mlp arch, the bigram DLM), round-trip verified (ggml reads them back). R4 step 8 seed, closed and tested.

Measured against

llama.cpp convert / quantizeHF → GGUF

To complete

Foundry rung 2 is unbuilt: corpus synthesis → tokenizer training → transformer training on ggml's backward → quantize → LLM GGUF. Today it exports small nets, not trained models.

12ONNX interopEmerging

In the engine

None. GGUF is the chosen and only model format; there is no ONNX import, runtime or export anywhere in the engine or faces.

Measured against

ONNX Runtimeonnx

To complete

ONNX is the interchange format for the wider model ecosystem (vision, classic ML, non-LLM nets). Choosing GGUF is defensible, but it closes the door on every ONNX-only model.

Ce qui est dû, dans l'ordre du rendement

Les manques, classés par ce qu'ils rapportent et non par leur taille ; la valeur est l'effet sur la portée de la bibliothèque, l'effort une lecture d'ingénieur.

Tier A — the production half

Wire ggml's backward pass — the training foundry

Invoke ggml-opt.cpp (vendored, dark) to train a transformer, closing foundry rung 2: corpus synthesis → tokenizer training → backward-pass training → LLM export. This is the line between "runs models" and "makes models."

Valeur · élevéeEffort · élevé
A quantization (encode) path

Q8_0 first, then the k-quant family — so exported or derived models ship at deployable size. De-quant already works on load; the encode side is the missing half and a precondition for a real foundry.

Valeur · élevéeEffort · moyen

Tier B — harden what runs

Ship or fetch a real semantic model

Commit a small real embedding model, or fetch-on-first-use, so the embedding, generative and rerank paths are exercised in CI rather than gracefully skipped. Turns "code proven by construction" into "path proven end-to-end."

Valeur · moyenneEffort · faible
Broaden the numeric bridge

Expose general ggml tensor ops (not just matmul) and a backward pass to the numeric plane — the doc's "ggml available to all numerics." It would also give the training foundry its gradient substrate.

Valeur · moyenneEffort · moyen
Extend GPU beyond the forward path

The calibration foundry now auto-routes the inference forward pass to GPU (2–5×). The reach is to cover the decoder generation loop and, eventually, training — and to move from per-shape kernel selection toward whole-graph GPU execution.

Valeur · moyenneEffort · moyen

Tier C — reach & breadth

More decoder architectures + speculative decoding

Beyond llama/qwen/smollm — the breadth llama.cpp carries — plus speculative decoding for throughput. Each new arch widens which local LLMs the tier can run.

Valeur · moyenneEffort · moyen
ONNX import

An ONNX loader would open the vision and classic-ML model ecosystem that GGUF does not cover. Strategic and against the current single-format bet — worth it only if non-LLM models become a goal.

Valeur · moyenneEffort · élevé
Convolutional & vision layers

The tier is text-transformer only — no conv layers, no vision models. Adding them (train and infer) would extend it beyond language into the image domain the perception frontier needs.

Valeur · faibleEffort · élevé
