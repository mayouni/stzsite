Palier neuronal

Un vrai moteur d'inférence, vérifié contre numpy (BERT et LLM, décodage contraint) ; l'entraînement et la fonderie sont dus.

4 Strong · 4 Solid · 3 Partial · 1 Emerging

Repensé depuis les premiers principes

Ce que Softanza a gardé de ce qui marche, et ce qu'elle a repensé, tel que la bibliothèque l'a écrit dans ses documents de conception et ses narrations.

La manière SoftanzaChaque capacité fonctionne sans aucun modèle, gagne en finesse quand un modèle local est présent, et ne dépend jamais d'un service payant ou distant.

Gardé des meilleures pratiques

  • Les modèles sont des fichiers GGUF standard, exécutés par le moteur ggml intégré. Softanza consomme d'abord le format commun, et n'apprend que plus tard à l'écrire. source(s'ouvre dans un nouvel onglet)
  • Le décodage contraint par une grammaire reprend l'algorithme de l'échantillonneur de llama.cpp, la référence pour GBNF. La machine elle-même est écrite en interne. source(s'ouvre dans un nouvel onglet)
  • L'encodeur de texte est vérifié contre une implémentation numpy indépendante du même calcul, dans une marge de tolérance mesurée. source(s'ouvre dans un nouvel onglet)

Repensé

  • La structure élimine les réponses mal formées, pas les mensonges. Une grammaire façonne la réponse pendant sa génération. Un tribunal vérifie ensuite les valeurs, ce qu'aucune grammaire ne sait faire. source(s'ouvre dans un nouvel onglet)
  • Un appel au modèle est une fonction pure et typée : le type déclaré ou un refus, un budget obligatoire, aucun pouvoir d'agir. Une réponse cassée ne passe jamais pour une valeur. source(s'ouvre dans un nouvel onglet)
  • Un fichier de modèle ne s'ouvre que si son empreinte correspond à une empreinte enregistrée. La vérification précède toute lecture, car c'est l'analyseur qui est exposé aux attaques. source(s'ouvre dans un nouvel onglet)
  • La consigne jointe à une demande structurée est fixée par la mesure. Des conseils supplémentaires ont fait tomber les réponses valides à 0 sur 10, et ont été retirés. source(s'ouvre dans un nouvel onglet)

The consumption side is complete and genuinely wired to a patched, vendored ggml: real GGUF loading, id-exact tokenizers, a numpy-parity BERT encoder, a multi-architecture causal LLM decoder with grammar-constrained decoding, and a measurement-gated GPU path. What is not there is the production side. A llama.cpp-class runner, wired into a governed library — not yet a training or model-production platform.

Ce qu'un artisan en fait, et ce qui se distingue

  • numpy-parity BERT encoder (1.64e-7)
  • grammar-constrained decoding wired to the structured-output contract
  • id-exact WordPiece and BPE tokenizers
  • measurement-gated wgpu GPU path (2-5x)

Ce qui est dû

  • wire ggml's backward pass -- the training foundry
  • a quantization (encode) path
  • ship or fetch a real semantic model for CI
  • ONNX import

La manière Softanza, exécutée

Ce que Softanza fait autrement dans ce domaine, montré par du code tiré de ses narrations et de ses gardes, et exécuté pour cette page.

Une réponse bien formée mais fausse passe quand même : le schéma garantit la forme, jamais la vérité, et le test montre cette limite exprès.

Softanza
oP = StzOutputSchemaQ([
	[ :field = "person", :type = :string ],
	[ :field = "age",    :type = :number, :must = [ [ ">=", 0 ], [ "<=", 130 ] ] ]
])
aLie = oP.ParseOutput('{ "person":"Ada Lovelace", "age":9 }')
chk("a schema-valid LIE validates -- Ada Lovelace was not nine", aLie[:ok] = 1)
chk("...and the court has no complaint to make about it", len(aLie[:findings]) = 0)

Les fonctions, par ce qu'elles font

Tester et vérifier

  • IsConstrainingDecoding Will the NEXT live call be grammar-constrained? Ask this rather than assuming: a nested structure, an off switch, or a build without the sampler rung all answer 0, and WhyNotConstrained() says which. dans stzLLMFunction
  • Check The family's rule face: run me, hand me back the findings. dans stzOutputSchema
  • IsDecodingConstrained Does anything actually CONSTRAIN DECODING with this grammar? Ask before reporting an answer as grammar-constrained. It answered 0 for as long as that was true; gbnf_machine.zig is the rung underneath it, so it answers 1 since 2026-08-20 -- the ENGINE is the authority on that number, never this comment. dans stzOutputSchema
  • IsExpressibleAsGrammar TRUE when this declaration can be expressed as a grammar at all. dans stzOutputSchema
  • IsLoaded load / unload (runtime gguf) dans stzNeuralModel
  • IsGenerative TRUE if this model can GENERATE text (a causal decoder). dans stzNeuralModel
  • IsReady stateless facade over the ggml inference backend. TRUE if the ggml backend is compiled in and executes. dans stzNeuralEngine

Trouver

  • LastFindings The findings the LAST validation produced, in the family's unified shape -- so a refusal can be handed to stzRuleReport.Ingest() and stand in the same CI gate as every other rule in the library. dans stzLLMFunction
  • SearchByVectorXT The same search from a query embedding the caller already holds (the companion of AddEmbedded). ONE search path serves both doors: the route -- CPU resident dataset or GPU resident corpus -- is decided here and nowhere else. dans stzSemanticIndex

Compter et mesurer

  • Count feeding the index dans stzSemanticIndex

Remplacer et modifier

  • SetRetrySampling The sampling a RETRY uses. Attempt 1 never sees these -- it is greedy. dans stzLLMFunction

Ajouter

  • AddGolden golden sets dans stzLLMFunction
  • AddText Embeds at ADD time (the model must be loaded), so a bad text fails loudly here and not in the middle of a search. dans stzSemanticIndex
  • AddTexts feeding the index dans stzSemanticIndex
  • AddEmbedded Index a text with an embedding the CALLER already has -- another model, a cache, a wire -- so the index never insists on embedding it again. The vector must be L2-normalised (the score formula assumes it) and of the index's dimension. dans stzSemanticIndex

Convertir

  • ToGBNF The GBNF text for this declaration, or a raise naming the construct that cannot be expressed. Nested structures are REFUSED rather than flattened: a grammar that accepted what this schema rejects would put the two layers into disagreement. dans stzOutputSchema
  • ParseOutput RAW MODEL TEXT to a validated whole, or to a refusal that names the rule it failed. [ :ok, :value, :findings, :shape ] dans stzOutputSchema

Lire et écrire

  • LoadFrom (Named LoadFrom, not Load -- "Load" collides with Haro's load keyword.) dans stzNeuralModel
  • LoadStatus Why the last LoadFrom was refused (0 ok, -1 unreadable, -2 digest mismatch, -3 no recorded digest). dans stzNeuralModel

Parcourir et appliquer

  • RunGoldens Goldens hold STRUCTURES as readily as scalars now. Two things had to change for that, and both were real defects rather than gaps: Haro's own `=` answers 0 for two identical lists, so a structured golden could never have passed; and a failing structured case that reports only "expected / got" is unreadable, so the failure now carries the FIELD that moved. dans stzLLMFunction
