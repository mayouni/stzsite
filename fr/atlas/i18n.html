Internationalisation

Un pari délibéré contre ICU : des données larges et une date-heure solide, mais ni collation, ni règles de pluriel, ni fuseaux horaires.

4 So4 P4 E

Mesuré contre: ICU/CLDR · Luxon · Babel · Dossiers: base/i18n · base/culture · base/datetime

A deliberate bet against ICU: rather than vendor tens of MB of C++ and CLDR data, Softanza ships broad hand-tables (261 countries, 323 languages, 143 scripts, Qt-sourced), a solid engine-backed datetime core with rich Haro-side formatting, and a distinctive business/holiday calendar. That same choice leaves the CLDR crown jewels absent: no locale collation, no ICU MessageFormat or plural rules, no translation catalog, no locale-aware number/currency formatting, no timezone database (ToUTC is a no-op), and no non-Gregorian calendars.

Ce qu'un maker en fait, et ce qui se distingue

  • Reference tables whose row coverage rivals CLDR (261 countries, 323 languages, 143 scripts)
  • A business/holiday calendar with sprint and capacity planning that most i18n libraries lack
  • An engine-backed datetime core with validated construction
  • Natural-language epoch parsing (FromNaturalEpoch)

Ce qui est dû

  • A timezone database (IANA/Olson zones, offset math, DST)
  • Locale-aware number and currency formatting over the hint tables that already ship
  • Fix the datetime / date / calendar / currency C22 test-runner collision (~450 assertions)
  • Locale-aware collation, CLDR plural rules and a translation catalog

Locale identity and reference data
Solid
261 countries, 323 languages, 143 scripts, 495 locale abbreviations, mirrored into engine SQLite (ref_data.zig / i18n.db); Qt-sourced, native names romanizedref_data.zig / i18n.db
Date / time types and arithmetic
Solid
stzDate/stzTime/stzDateTime engine-backed (datetime.zig): components, leap, add-days, diff, compare, ISO/Unix round-trips; month/year add is Haro-side; naivedatetime.zig
Date / time formatting and parsing
Solid
~40 named formats over Qt/Unicode tokens, multi-format and natural-language epoch parsing; all Haro-side, the engine stz_date_format always emits ISO
Business and holiday calendar
Solid
stzCalendar: quarters, weeks, working-day arithmetic, holidays, capacity and sprint planning, heat-map; plus engine-backed stzTimeLine; pure Haro, GregorianstzCalendar; test/timeline (54 assertions)
Currency
Partial
Engine-backed (the L1 cutover) stz_locale_currency_iso / _symbol over 143 rows with a property test; symbol / ISO lookup only, no amount formattingstz_locale_currency_iso / _symbol property test
Number formatting
Partial
StzFormatNumber groups and rounds; Haro holds per-locale separator hints (~30 languages) but the engine formatter hardcodes US separators and never reads themStzFormatNumber
Native names and per-locale text
Partial
Native day and month names for 11 languages via NamesOfDaysIn / NamesOfMonthsIn; all else falls back to English; engine day_name takes no locale (L3 work)NamesOfDaysIn / NamesOfMonthsIn
Calendar systems
Partial
Proleptic Gregorian only, hardcoded in datetime.zig (gregorianToJulian); no Hijri, Persian, Hebrew, Buddhist or Japanese calendarsdatetime.zig gregorianToJulian
Timezones
Emerging
None: datetimes are naive wall-clock; ToUTC() and ToLocalTime() are no-ops that copy the components unchanged
Collation (locale-aware sorting)
Emerging
None: the only collate in the tree is SQLite COLLATE NOCASE (ASCII case-insensitive), not linguistic collation
Message formatting and pluralization
Emerging
None: the only plural handling is an English singular/plural pair in stzDuration; no ICU MessageFormat, no CLDR plural rules, no gender/select
Translation / message catalog
Emerging
None: no gettext, no .po / .mo, no message catalog anywhere in the group
