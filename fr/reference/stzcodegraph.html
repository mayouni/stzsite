la source: base/meta/stzCodeGraph.ring(s'ouvre dans un nouvel onglet) · Toutes les classes · La référence du domaine : Métaprogrammation et règles de code

Un programme lu comme graphe : ses classes, méthodes, fonctions, héritages, importations et, avec un vrai analyseur, ses appels ; si bien que les questions d'un mainteneur, qui définit ceci, qui en hérite, que casse-t-on en le changeant, qu'est-ce qui n'est jamais appelé, trouvent réponse par une requête et non par une recherche.

On le pointe sur une racine, pour le langage que sa sous-classe connaît, et la source est analysée par la grammaire tree-sitter embarquée dans le moteur, sans qu'aucun environnement de ce langage soit requis. Puis il répond sur la structure : les classes, les méthodes d'une classe, chaque classe qui définit une méthode, un parent, la filiation jusqu'à une racine, les sous-classes et descendants, les importations, le fichier.

La question à poser avant une modification est l'impact d'une méthode : les classes qui la définissent plus chaque descendant qui l'hérite sans la redéfinir. Avec les arêtes d'appel, il répond aussi qui appelle quoi, quelle routine définie aucun appel enregistré n'atteint, et quelles routines peuvent s'atteindre elles-mêmes.

Les règles de code courent sur le graphe et répondent des constats dans la forme unifiée de la bibliothèque, chacun avec classe, méthode et ligne, ce qui met la porte des boutons et les autres règles de code dans un seul rapport d'intégration avec les règles de graphe de tous les autres domaines. Il sert une refonte, une revue, une prise en main, une migration entre langages, et l'auto-documentation de la bibliothèque, qui se lit elle-même par cette classe.
