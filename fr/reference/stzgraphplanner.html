stzGraphPlanner

139 méthodes propres · 82 formes avec extensions, rangées sous leur méthode

la source: base/graph/stzGraphPlanner.ring(s'ouvre dans un nouvel onglet) · Toutes les classes · La référence du domaine : Diagrammes et graphes

stzGraphPlanner est une classe qui trouve le chemin le moins cher dans un graphe. Un graphe est un ensemble de nœuds reliés par des arêtes. On donne à la classe des plans nommés. Chaque plan a des critères, comme une distance, un coût, un risque ou un mélange de ces éléments, et la classe garde les plans exécutés pour que vous puissiez comparer ce que chacun a choisi.

Elle sert pour des questions comme la route la plus courte entre deux villes, ou le chemin le moins cher à travers un réseau de services. Un plan a un départ et un but. Le but est un nœud, ou une fonction qui teste les nœuds. Les critères sont des propriétés des arêtes que le plan doit minimiser ou maximiser. À la place des critères, un plan peut utiliser un profil : le plus rapide, le plus sûr, le moins cher, le plus court, équilibré ou efficace.

L'exemple ci-dessous construit un graphe de trois nœuds, a, b et c. Le passage par b est court (distance 5 + 5) mais coûteux (coût 1 + 9). L'arête directe de a à c est longue (distance 20) mais bon marché (coût 2). Le premier plan minimise la distance et renvoie a, b, c. Le second plan minimise le coût et renvoie a, c.

g1 = new stzGraph("g1")
g1 {
    AddNodeXTT("a", "A", [ :x = 0 ])
    AddNodeXTT("b", "B", [ :x = 1 ])
    AddNodeXTT("c", "C", [ :x = 2 ])

    AddEdgeXTT("a", "b", "r", [
        :distance = 5,
        :cost = 1
    ])
    AddEdgeXTT("b", "c", "r", [
        :distance = 5,
        :cost = 9
    ])
    AddEdgeXTT("a", "c", "r", [
        :distance = 20,
        :cost = 2
    ])
}

o1 = new stzGraphPlanner(g1)

# the shortest way from a to c
o1.AddPlan("short")
o1.Walk("a", "c")
o1.Minimize("distance")
o1.Execute()
? @@( o1.Route() )
#--> [ "a", "b", "c" ]

# the cheapest way is another route
o1.AddPlan("cheap")
o1.Walk("a", "c")
o1.Minimize("cost")
o1.Execute()
? @@( o1.Route() )
#--> [ "a", "c" ]
exécuté dans la bibliothèque le 2026-10-21

La recherche s'exécute dans le moteur comme une recherche à coût uniforme, qui prolonge toujours d'abord le chemin partiel le moins cher. Le chemin trouvé est donc le moins cher dès qu'aucun coût n'est négatif. Chaque exécution est gardée dans un historique. Les plans exécutés peuvent être comparés, classés et filtrés, ce qui montre pourquoi un chemin a été choisi et ce que l'autre aurait coûté. Le planificateur prend une copie du graphe quand il est construit, si bien qu'une arête ajoutée ensuite n'est pas vue.

Utilisez-la pour une question de logistique, pour un flux de travail dont les étapes ont des coûts, ou pour un chemin à travers un réseau de services.
