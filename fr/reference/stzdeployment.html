Steps
the plan of steps (order, gates, rollback) --------- the deployment PLAN as ordered steps. A simple deployment is the default chain per part -- provision? -> store -> launch -> verify; After() edges add cross-part ordering (a frontend after its backend). Returns [ [name, op, part, siteName, [needs]], ... ], topologically ordered so every dependency precedes its dependants.aucune extension
WasRun
EXECUTE the ordered plan (governed). Each step runs its op; the verify step is a GATE (the site must be launched). On any failure, the completed store/launch steps are ROLLED BACK in reverse -- the deployment is transactional. Returns [ committed(0/1), [ [stepName, outcome], ... ] ]. No effectful actor -> rehearse. Did Run() execute at all? A deployment REFUSED upstream -- by the service gate in stzDelivery, say -- comes back untouched, and "nothing happened" is then assertable without reading the log.aucune extension
