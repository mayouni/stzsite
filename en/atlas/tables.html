Tables & data

Broad unified data frame with a pattern language, but no join, and a group-by that runs outside the engine.

2 Strong · 6 Solid · 3 Partial · 1 Emerging

Measured against: pandas · Polars · DuckDB · Folders: base/table(opens in a new tab) · base/data(opens in a new tab) · The guide to this area's functions

Rethought from first principles

What Softanza kept from what works, and what it rethought, as the library wrote it down in its design documents and narrations.

The Softanza wayA table is a grid people read like a spreadsheet — named columns, rows and cells — and every column is a list you can question.

Kept from the best practice

  • Data is stored by column, because columns have names and rows do not, and data analysis treats every variable as a column. source(opens in a new tab)
  • Familiar spreadsheet functions (SUM, AVERAGE, MIN, MAX, PRODUCT), grouping with aggregates, and pivot tables work on a table directly. source(opens in a new tab)
  • Standard formats in and out: CSV, JSON and HTML tables, plus real SQL through an embedded SQLite database (stzDatabase). source(opens in a new tab)

Rethought

  • Methods use plain words — AddRow, RemoveCol, Cell, FindInCol — that follow how people think about tables, rather than a technical data-frame vocabulary, so learning stays gentle. source(opens in a new tab)
  • A column is a list: whatever you ask a list — sum it, filter it by a condition — you can ask a column, so knowing lists already means knowing tables. source(opens in a new tab)
  • Tables are validated by pattern: one stzTablex expression states shape, unique keys, missing values and averages, instead of procedural checking code. source(opens in a new tab)
  • A table hands a column to the statistics object instead of recomputing statistics itself, because duplicated definitions drift: two classes once disagreed on a variance (4 versus 4.57). source(opens in a new tab)

One enormous unified class, 2,517 methods with eleven sibling caps merged into a single stzTable, with engine-backed sort, aggregates, calculated columns, describe and pivot, plus a distinctive multi-table TableX pattern-query language. Measured against pandas, Polars and DuckDB it has three real holes: there is no join at all; group-by and filter run Haro-side even though engine bridges for both sit exported-but-unused; and the columnar engine is used per-operation, not as the live store.

What a maker does with it, and what stands out

  • A multi-table TableX pattern-query language with no direct peer
  • A copy-free index-permutation engine sort
  • Engine-first calculated columns, compile-once over all rows, guarded at 50k rows
  • Eleven sibling caps merged into one stzTable namespace

What is owed

  • Add joins: there is no join anywhere in the tables lane
  • Wire group-by and filter to the engine bridges already compiled and exported
  • Finish the 11-to-1 fidelity grind (150 of 251 legacy tests error)
  • Missing-data toolkit (fillna / dropna) and melt / unpivot

The Softanza way, run

What Softanza does differently in this area, shown by code taken from its narrations and guards, and run for this page.

A column is a list, so it can be summed or searched with a condition like any list.

Softanza
oT = new stzTable([
	[ :DISH, :PRICE, :ORDERS ],
	[ "tea",  200, 6 ],
	[ "rice", 500, 3 ],
	[ "fish", 900, 2 ]
])
? StzListQ(oT.Col(:ORDERS)).Sum()
? @@( StzListQ(oT.Col(:PRICE)).FindW("{ @item > 400 }") )
Output

[ 2, 3 ]

oT = new stzTable([
	[:age,    [20, 25, 30, 35, 40]],

Then("MedianCol(age) is 30", oT.MedianCol(:age), 30)
