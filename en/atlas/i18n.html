Internationalization

A deliberate bet against ICU: broad data and solid datetime, but no collation, plural rules or time zones.

4 Solid 4 Partial 4 Emerging

Measured against: ICU/CLDR · Luxon · Babel · Folders: base/i18n(opens in a new tab) · base/culture(opens in a new tab) · base/datetime(opens in a new tab) · For programmers: this area's reference

A locale says how a value is written down; a culture says how it will be read. Softanza keeps the two apart, and refuses to infer a meaning from a locale code alone.

The data is owned and committed: 261 countries, 323 languages, 143 scripts, 495 locale abbreviations, generated offline and stamped with their source, so a locale resolves with nothing to download. new stzLocale("fr_FR") knows its currency's ISO code and the sign people write; new stzLocale("fa_IR") starts its week on Saturday and names the day in Persian. Dates and times are engine-backed, with validated construction, ISO 8601 round trips and some forty named formats.

Then comes the part most libraries do not have: time is modelled, not only measured. One stzTimeLine holds events, spans and blocked windows, checks every insertion against them, and draws itself; stzCalendar knows working days, holidays, quarters, sprints and capacity. An event placed inside a maintenance window is refused the moment it is added.

This was a deliberate bet against ICU: no tens of megabytes of C++ and CLDR data. The bet has a price the page names plainly. There is no locale-aware collation, no plural rules or message formatting, no translation catalogue, no time-zone database, no calendar but the Gregorian. Four lanes rate Solid, four Partial, four Emerging. The next culture plane adds the missing half of the principle: an operation honours the culture it was given, or refuses, because ignoring a locale silently looks like success and returns wrong text.

Where it stands

The Softanza Compass's reading: every lane of the area rated against the best of its category, by what the guards prove. Read from the source on 2026-09-16. The Compass's sentences are in English, as it wrote them.

This module is a deliberate bet against ICU. Rather than vendor tens of MB of C++ and CLDR data, Softanza ships broad hand-tables (261 countries, 323 languages, 143 scripts, Qt-sourced), a solid engine-backed datetime core with rich Haro-side formatting, and a distinctive business/holiday calendar. But that same choice leaves the CLDR crown jewels absent: no locale collation, no ICU MessageFormat or plural rules, no translation catalog, no locale-aware number/currency formatting, no timezone database (ToUTC is a no-op), and no non-Gregorian calendars. The data and the datetime basics are solid; almost everything that makes ICU, Babel and Luxon what they are is still owed.

The honesty line on the ratings. The clean-loading test dirs pass — time, timeline (54), timex, i18n, script, and locale (81/94) — and the engine Zig tests guard currency and datetime. But datetime, date, calendar and currency report large ERR counts that are all one C22 runner-load collision, not per-assertion failures, so those lanes' guards can't fully vouch until it's fixed. The engine locale functions (casing, AM/PM, number, day names) remain English/ASCII/US stubs.

The one-sentence position. Softanza traded ICU's weight for owned, committed data — and it shows on both sides: broad reference tables and a solid, well-formatted Gregorian datetime with a standout business calendar, but none of the CLDR machinery (collation, plural/message formatting, timezones, locale number formatting, multiple calendars) that the category leaders are defined by.

What a crafter does with it, and what stands out

  • Reference tables whose row coverage rivals CLDR (261 countries, 323 languages, 143 scripts)
  • A business/holiday calendar with sprint and capacity planning that most i18n libraries lack
  • An engine-backed datetime core with validated construction
  • Natural-language epoch parsing (FromNaturalEpoch)

What is owed

  • A timezone database (IANA/Olson zones, offset math, DST)
  • Locale-aware number and currency formatting over the hint tables that already ship
  • Fix the datetime / date / calendar / currency C22 test-runner collision (~450 assertions)
  • Locale-aware collation, CLDR plural rules and a translation catalog

Rethought from first principles

What Softanza kept from what works, and what it rethought, as the library wrote it down in its design documents and narrations.

The Softanza wayA locale says how a value is written down; a culture says how it will be read, and no meaning may be inferred from a locale code alone.

Kept from the best practice

  • Standard identifiers: locales are created from IETF language tags such as ar-TN, and currencies are keyed by their ISO codes. source(opens in a new tab)
  • ISO 8601 for data exchange and logs, and a 24-hour clock by default, for precision and international clarity. source(opens in a new tab)
  • Unicode normalization in all four standard forms and script detection come from the shared Unicode library rather than home-made tables. source(opens in a new tab)

Rethought

  • No ICU: the locale data the library actually answers is generated offline and committed with its source stamped, avoiding tens of megabytes of dependency. source(opens in a new tab)
  • A locale formats; a culture interprets: a meaning such as red-for-loss is never derived from a locale code, since red means gain in some financial cultures. (planned) source(opens in a new tab)
  • No facades: an operation honours the culture it was given or refuses, because ignoring a locale silently looks like success and returns wrong text. (planned) source(opens in a new tab)
  • Time is modelled, not just measured: one timeline object holds events, spans and blocked zones, checks them on insertion and draws them, instead of stitched-together tools. source(opens in a new tab)

12 lanes, each against the best of its category

For every lane: what runs in the engine today, the tools it is fair to measure it against, and what is still owed.

01Locale identity & reference dataSolid

In the engine

Broad tables: 261 countries, 323 languages, 143 scripts, 495 locale abbreviations, with language↔country↔script defaults (stzLocale, stzCountry, stzLanguage, stzScript), now mirrored into an engine SQLite layer (ref_data.zig / i18n.db).

Measured against

ICU / CLDRBabel

To complete

Row coverage rivals CLDR, but the data is Qt-sourced, not CLDR, "native" names are romanized English, and Haro and engine hold parallel copies (L2 cutover incomplete).

02Date / time types & arithmeticSolid

In the engine

stzDate / stzTime / stzDateTime are engine-backed (datetime.zig): components, leap/day-of-year, add-days, diff, compare, is-between, ISO and Unix round-trips. Validated construction (invalid dates return null).

Measured against

LuxonTemporalICU calendar

To complete

Month/year addition is done Haro-side (no engine add-months), and every value is naive wall-clock — the offset math a real datetime type carries lives in the timezone gap (lane 9).

03Date / time formatting & parsingSolid

In the engine

Rich Haro-side formatting: ~40 named formats (:ISO8601, :European, :Verbose, :Compact12h…) over Qt/Unicode pattern tokens, plus multi-format parsing and natural-language epoch parsing (FromNaturalEpoch).

Measured against

LuxonBabelstrftime

To complete

All Haro-side — the engine stz_date_format ignores its format string and always emits ISO. No CLDR skeleton formats, and formatting is not locale-tailored beyond the named presets.

04Business & holiday calendarSolid

In the engine

stzCalendar — a genuinely rich Gregorian working-days / holiday calendar: quarters, weeks, working-day arithmetic, holidays, capacity and sprint planning, with a heat-map view. Plus an engine-backed stzTimeLine.

Measured against

workalendarbizdayspandas bdate_range

To complete

A distinctive plus most i18n libraries lack — but pure Haro, Gregorian-only, and its test directory currently can't run (lane note below).

05CurrencyPartial

In the engine

Engine-backed (the L1 cutover): stz_locale_currency_iso / _symbol over 143 rows, guarded by a "no row answers its own ISO code" property test.

Measured against

ICUBabel numbersIntl.NumberFormat

To complete

Symbol / ISO lookup only — no amount formatting with locale placement, spacing, grouping or minor-unit rules. The actual currency-formatting job is not done.

06Number formattingPartial

In the engine

StzFormatNumber formats with grouping and decimals — and Haro holds per-locale decimal/group-separator hint tables (~30 languages).

Measured against

ICU NumberFormatIntl.NumberFormatBabel

To complete

Not locale-aware: the engine formatter hardcodes US ,/. and never reads the hint tables. The data exists; wiring it in is the whole gap.

07Native names & per-locale textPartial

In the engine

Native day and month names for 11 languages (english, french, arabic, persian — now native-script — spanish, german, portuguese, italian, russian, turkish, dutch), via NamesOfDaysIn / NamesOfMonthsIn.

Measured against

CLDR (hundreds of locales)Babel

To complete

Eleven of hundreds — everything else falls back to English, and the engine day_name still takes a number and no locale (the L3 work). Reference "native" names elsewhere are romanized.

08Calendar systemsPartial

In the engine

Proleptic Gregorian only, hardcoded in datetime.zig (gregorianToJulian and back). The business calendar above is the depth on this single system.

Measured against

ICU (Hijri / Persian / Hebrew / Buddhist / Japanese)Luxon

To complete

No Hijri, Persian, Hebrew, Buddhist or Japanese calendars — a notable absence given the library's strong Arabic/Persian typography elsewhere.

09TimezonesEmerging

In the engine

None. Datetimes are naive wall-clock — ToUTC() and ToLocalTime() are no-ops that copy the components unchanged.

Measured against

Luxon (IANA)ICU / tz databasemoment-timezone

To complete

An IANA/Olson timezone database, offset math and DST. Without it, no correct cross-zone arithmetic — the single biggest gap against Luxon.

10Collation (locale-aware sorting)Emerging

In the engine

None. The only "collate" in the tree is SQLite COLLATE NOCASE (ASCII case-insensitive lookup), not linguistic collation.

Measured against

ICU Collator (the crown jewel)Intl.Collator

To complete

Locale-aware sorting is ICU's headline feature and is entirely absent — shared with the String page's top gap. The one thing that most defines an i18n library.

11Message formatting & pluralizationEmerging

In the engine

None. The only plural handling is an English singular/plural pair for duration wording in stzDuration.

Measured against

ICU MessageFormatCLDR plural rulesi18next / Fluent

To complete

No ICU MessageFormat, no CLDR plural rules (one/few/many/other), no gender/select — the machinery real translation depends on.

12Translation / message catalogEmerging

In the engine

None. No gettext, no .po / .mo, no message catalog anywhere in the group.

Measured against

gettextBabel catalogsi18next / Fluent

To complete

A catalog format and lookup — the actual "translate a string into locale X" surface. Everything above is locale data; there is no translation layer yet.

What is owed, in the order of return

The gaps, ordered by what they bring and not by their size; value is the effect on the library's reach, effort an engineer's reading.

Tier A — foundational

A timezone database

IANA/Olson zones, offset math and DST, so ToUTC / ToLocalTime stop being no-ops and cross-zone arithmetic becomes correct. The single biggest gap against Luxon, and a precondition for any global scheduling use.

Value · highEffort · high
Locale-aware number & currency formatting

Wire the existing decimal/group-separator hint tables (and currency placement/minor-unit rules) into the engine formatter. The data already ships; the formatter just hardcodes US — a high-leverage fix over existing tables.

Value · highEffort · medium

Tier B — cheap and high-leverage

Fix the datetime test-runner collision

The datetime / date / calendar / currency dirs error en masse on one C22 Function redefinition load collision — not logic failures. Fixing it lets those ~450 assertions actually vouch for the lanes.

Value · highEffort · low
CLDR plural rules + minimal MessageFormat

Generate the CLDR plural categories offline (as the "not ICU" decision already does for other data) and a small MessageFormat parser — the base translation real apps need.

Value · mediumEffort · medium
Broaden native day/month names

Lift the 11-language ceiling by generating names from the offline source, and give the engine day_name a real locale argument (the L3 work).

Value · mediumEffort · low

Tier C — the CLDR reach

Locale-aware collation

The crown jewel — locale sorting via a generated CLDR collation subset. Shared with the String page's top gap; closing it once serves both.

Value · highEffort · high
Non-Gregorian calendars

Hijri, Persian and Hebrew at least — conspicuously missing given the library's strong Arabic/Persian typography elsewhere.

Value · mediumEffort · high
A translation catalog + finish the engine cutover

A gettext-style or Fluent-style message catalog, and completing L2–L4 so the engine registry (already built) retires the parallel Haro tables and becomes the single source of truth.

Value · mediumEffort · medium
