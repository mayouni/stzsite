Collections & objects

Engine-backed functional pipeline plus a reflective object root; boxed storage caps native set-op speed.

6 Strong 5 Solid 1 Partial

Measured against: Lodash · Immutable.js · standard libraries · Folders: base/list(opens in a new tab) · base/object(opens in a new tab) · For programmers: this area's reference

Collections in Softanza are strings, lists, hash lists and the other structures that hold several values, and the same few questions work on all of them: does it contain this value, how many are there, where is it. A hash list is a list of key-value pairs. Only the unit of position changes: a character in a string, an item in a list, a key in a hash list.

Finding is therefore one function with one shape of answer, whether the host is a string or a list. The class stzList has 1,600 methods. Behind them is a core of about 155 operations, written in Zig in 6,500 lines: finding, slicing, sorting, set operations, grouping, zipping (pairing the items of two lists) and windows (successive blocks of items). The engine runs all of them and they are tuned for millions of items. The example below finds 'tea' in the string 'tea rice tea fish' and in the list ['tea', 'rice', 'tea', 'fish'], and returns the positions [1, 10] and [1, 3].

# one function, whether the host is a string or a list
? @@( StzFind("tea", "tea rice tea fish") )
#--> [ 1, 10 ]

? @@( StzFind("tea", [ "tea", "rice", "tea", "fish" ]) )
#--> [ 1, 3 ]
run in the library on 2026-10-20

A predicate is a condition that an item must meet. You can write it as a string, and the engine then runs it itself; none of the peer libraries compared does this. You can also write the predicate as a function, when you prefer the language. The example below keeps the numbers greater than 10 in the list [5, 12, 8, 30] and returns [12, 30].

o1 = new stzList([ 5, 12, 8, 30 ])

# a predicate written as a string runs inside the engine
? @@( o1.Filter('@item > 10') )
#--> [ 12, 30 ]
run in the library on 2026-10-20

The form of a method name tells its effect, and this is the grammar of the whole library. The plain verb changes the object itself. Its past form returns a changed copy and leaves the object alone. A final Q makes the call chainable, so another call can follow directly. A chain can keep its history, every step from the starting value to the result, which a transformation normally does not record. Truth can also be configured: you can declare that 'no' and 'off' make a string false, and a string such as 'no way' is then answered accordingly. The example below adds 1 to the list [5, 3, 8] in two ways. The past form returns [5, 3, 8, 1] and the list stays [5, 3, 8]. The plain verb then changes the list itself, which becomes [5, 3, 8, 1].

o1 = new stzList([ 5, 3, 8 ])

# the past form returns a copy and leaves the list alone
? @@( o1.Added(1) )
#--> [ 5, 3, 8, 1 ]

? @@( o1.Content() )
#--> [ 5, 3, 8 ]

# the plain verb changes the list itself
o1.Add(1)
? @@( o1.Content() )
#--> [ 5, 3, 8, 1 ]
run in the library on 2026-10-20

Every object in the library inherits from one root class, stzObject. Its 449 classes share introspection (asking an object about its own content and methods), comparison, cloning and Q-elevation, which turns a raw value into a chainable object. Around the list there are specialised collections: hash lists, grids, trees, sets, lists of pairs, lists of sections and lists of lists. A grammar of 1,945 methods with named parameters lets a call read close to English.

Two limits are specific. Values are boxed (each value is wrapped in an object), so the raw throughput of set operations stays about ten times below NumPy-native. There are no persistent immutable structures (structures that share their unchanged parts between versions), so a modified copy of a large list is a full copy. The work that keeps a list inside the engine between calls is measured at 2.6 times faster on re-reads at a million items, and half of it is migrated. Use NumPy when you need raw throughput on large numeric sets.

Where it stands

The Softanza Compass's reading: every lane of the area rated against the best of its category, by what the guards prove. Read from the source on 2026-09-16. The Compass's sentences are in English, as it wrote them.

This is one of the largest surfaces in the library: ~155 list operations in a 6,500-line Zig core behind a 1,600-method Haro face, a functional pipeline, deep-path search, Lodash-grade grouping, and a reflective object root that 449 classes inherit. It is tuned for millions of items with measured residency wins. Two honest limits keep it short of the very top: boxed value storage holds raw set-op throughput an order of magnitude below NumPy/native, there are no persistent immutable structures, and the legacy test grind is mid-flight — so the ratings lean on the narrated and engine suites that pass.

The honesty line on the ratings. The core is proven: 00_list_narrated (79 assertions), the large-scale guards, and ~30 test_* engine/delegation checkers all pass. But the ~602-file legacy suite is mid-grind — 312 blocks error, dominated by renamed-method calls, and the object module carries a stale expectation (HowManyStzClasses()=60 when 449+ classes now inherit the root). The lane ratings describe the engine-backed capability the trustworthy suites exercise, not the full alias surface that grind will reconcile.

The one-sentence position. Softanza's collections are broader and more engine-backed than any single stdlib or Lodash — a functional pipeline, deep search, Lodash-grade grouping and a reflective object root, tuned for millions — and its distance from the very top is two specific things: boxed storage (vs NumPy-native throughput) and the absence of persistent immutable structures (vs Immutable.js).

What a crafter does with it, and what stands out

  • String-expression predicates run inside the engine, which the peers cannot do
  • A deep-path search API that Lodash get only approximates
  • A reflective object root 449 classes inherit, with Q-elevation and the Verb/Verbed/VerbQ grammar
  • Measured residency wins at 1M items: 2.6x read-reuse, Classify -51%, Union -34%

What is owed

  • Finish the list narration / fidelity grind (312 of ~602 legacy blocks error)
  • Unboxed typed storage for native-speed set-ops
  • Complete the residency migration (Slices 4 and 5, ~32 marshal-in sites)
  • Persistent immutable collections with structural sharing

Rethought from first principles

What Softanza kept from what works, and what it rethought, as the library wrote it down in its design documents and narrations.

The Softanza wayThe same few questions — does it contain, how many, where — and the same verbs work on every structure; only the unit of position changes.

Kept from the best practice

  • Default truth stays the platform's own: empty is false, something is true; IsTrue() behaves exactly like the native test before any extension. source(opens in a new tab)
  • Keeps the usual safe-lookup discipline: check that a key exists (HasKey, HasPath) before reading it, so a lookup never silently creates an empty entry. source(opens in a new tab)

Rethought

  • Strings and lists answer the same verbs — Contains, NumberOfOccurrence, FindAll — and StzFind accepts either, so one way of thinking covers every structure. source(opens in a new tab)
  • A method's form carries its effect: Remove() changes the object, Removed() returns a changed copy, RemoveQ() chains, so side effects are visible in the name. source(opens in a new tab)
  • Truth can be configured: IsTrueXT() lets a program declare which items or words make a list or string false, instead of one fixed empty-equals-false rule. source(opens in a new tab)
  • An object can keep the story of its changes: QH() records every step of a chain, because a transformation normally leaves no trace of its path. source(opens in a new tab)

01Core list operationsStrong

In the engine

Index, slice, section, insert, remove, reverse, swap, rotate, repeat — the full vocabulary, reads and reverse engine-backed via stz_list_get/slice/reverse/rotate. Mutators route through Haro submodules (stzListInserter/Remover/Mover) then re-cache.

Measured against

Python listRust VecC++ std::vectorLodash

To complete

Comprehensive and correct. The only structural note is that mutators still make a Haro hop before invalidating the engine cache — a residency detail, not a capability gap.

02Functional pipeline (map · filter · reduce)Strong

In the engine

Engine-backed map_expr / filter_expr / reduce_expr using a string DSL (@item, @accumulator), plus two predicate modes: W (string-expression, engine) and WF (Haro function, in-VM) across Find/Filter/Count/Positions/Remove/Replace.

Measured against

LodashPython functools / comprehensionsRust iterators

To complete

A real, dual-mode functional surface. The string-expression path even runs the predicate in the engine, which the peers cannot do — a genuine differentiator.

03Search · find · contains · deep pathsStrong

In the engine

The full finder family engine-backed (find_cs, find_all_cs, find_nth_cs, contains_cs, starts/ends_with) plus a deep-path API (deep_find, item_at_path, paths_at_depth) that Lodash-style get only approximates.

Measured against

Lodash (get / find)PythonRust

To complete

Cross-module needle handles are already solved (find_all_held_cs). Nothing structural owed on the search lane.

04Set operationsSolid

In the engine

Union, intersection, difference, subset, unique — all engine-backed (stz_list_union_cs etc.) with a scalar splitmix64 fast path for int/float keys (1M int-union ~43% faster).

Measured against

Python setLodashImmutable.js Set

To complete

A footgun to know: intersection_cs dedups (true set) while common_items_cs keeps left order and duplicates (multiset). And boxed storage keeps 1M int-union at ~2–3s vs Python's ~0.1s — the unboxed frontier (lane 9).

05Grouping · partition · chunk · zipStrong

In the engine

Full Lodash-grade reshaping, engine-backed: classify_cs, partition, chunked, split_to_parts_of_n, zip, interleave, sliding_window, frequencies_cs — classify even emits the final nested shape engine-side (−51% at 1M).

Measured against

Lodash (groupBy / chunk / zip)Python itertools / collections

To complete

Broad and fast. A window / stream abstraction that returns lazily (rather than materialising) would be the only refinement worth naming.

06Sorting & orderingStrong

In the engine

sort, sort_cs, sort_descending, sort_by_expr (key expression), sort_on, sorted_insert, and a full predicate set (is_sorted, is_strictly_increasing, is_monotonic) — all engine-backed.

Measured against

Python sorted / keyLodash sortByRust sort_by

To complete

At parity, with a case-sensitivity dial and key-expression sorting the peers match but rarely improve on.

07Aggregation & statistics on listsSolid

In the engine

Stats built into the collection, engine-backed: sum, product, mean, median, variance, stddev, nth_largest, ranked — also surfaced on stzListOfNumbers.

Measured against

LodashPython statisticsNumPy (reductions)

To complete

A useful bonus on a collection, but the deep statistical story (distributions, tests, the careful compensated summation) lives on the Statistics page — rated Solid here as a convenience lane.

08Immutability & copy semanticsPartial

In the engine

Haro assigns lists by value — copy-on-assign and copy-on-return — which gives safety by default (no accidental aliasing) and a clean Copy(). The residency layer works with this rather than against it.

Measured against

Immutable.jsClojure persistent collsRust im crate

To complete

No persistent immutable structures with structural sharing: a "modified copy" of a large list is a full copy, not an O(log n) share. The whole residency effort (lane 9) exists to soften exactly this cost.

09Large-scale performance & residencySolid

In the engine

A measured residency system: a bounded, generation-keyed cache (FIFO eviction at 8M items / 1024 entries, so the 8192-slot handle table never overflows) plus copy-elimination on unmarshal. Measured: read-reuse 3.34s→1.29s (2.6×), Classify −51%, Union −34% at 1M items.

Measured against

NumPy (unboxed)Rust VecPython list

To complete

Items are boxed *StzValue, so native-speed set-ops need unboxed typed storage (deferred). And the migration is half-done: Slice 4 (engine-truth) and Slice 5 (submodule residency) are open, with ~32 marshal-in sites remaining.

10The object system (stzObject root)Strong

In the engine

One reflective root inherited by 449 classes: introspection (Attributes, Methods, Type, ObjectUID), comparison, cloning, Q-elevation (Q(...) lifts a raw value into a chainable object), and the function-form grammar — Verb() mutates, Verbed() copies, VerbQ() chains.

Measured against

Python object / reflectionRubyJS Object / Reflect

To complete

The root's own #TODO notes the common surface is not fully abstracted — some behaviour is duplicated across children for semantic reasons. A consolidation, not a capability gap.

11Specialized collectionsSolid

In the engine

A wide family: stzHashList / associative list, stzGrid, stzTree, stzSet, stzListOfLists / 2D, stzListOfPairs, stzListOfSections, stzYielder — the structured-collection catalogue.

Measured against

Python collectionsImmutable.js (Map/Record)Lodash

To complete

Most of this family is Haro-side (not scale-tuned), and stzHashList folds keys to lowercase and is not a true hash map — a documented trap. Rich, but shallower than the core list under the engine.

12Named-parameter grammarSolid

In the engine

stzListNamedParams — a 1,945-method grammar for natural-language named arguments (IsOnSection, IsHarvest, IsYield…NamedParam) that lets call sites read close to English. A distinctive Softanza mechanism with no direct peer.

Measured against

Python kwargsRuby keyword args(no direct peer)

To complete

Pure Haro, and its correctness under the fidelity grind (lane note below) is the least-verified of the group. A powerful, distinctive surface carrying real coverage debt.

What is owed, in the order of return

The gaps, ordered by what they bring and not by their size; value is the effect on the library's reach, effort an engineer's reading.

Tier A — foundational

Finish the list narration / fidelity grind

About 312 of ~602 legacy test blocks error — mostly R14 "method without definition" from renamed aliases — and the fidelity marker pass is uncaptured. The core is proven by the narrated and engine suites, but closing this turns the whole advertised surface from claimed into guarded.

Value · highEffort · medium
Unboxed typed storage for native-speed set-ops

Items are boxed *StzValue, so a 1M int-union runs ~2–3s against Python's ~0.1s. Typed unboxed arrays for scalar lists would close the last order-of-magnitude gap — the deliberately-deferred frontier.

Value · highEffort · high

Tier B — finish work already in flight

Complete the residency migration

Slice 4 (engine-truth / lazy @aContent) and Slice 5 (submodule residency) with the ~32 remaining marshal-in sites. The infrastructure and measurements exist; this is finishing a measured win, not starting one.

Value · mediumEffort · medium
Disambiguate the set-op semantics

Make the set-vs-multiset choice explicit at the API so intersection_cs (dedups) and common_items_cs (keeps order + duplicates) can't be confused silently — a naming/doc fix over correct engine code.

Value · mediumEffort · low
Consolidate the object root

Act on stzObject's own #TODO: abstract the common behaviour duplicated across children. Reduces surface area and drift across 449 classes.

Value · lowEffort · medium

Tier C — strategic reach

Persistent immutable collections

Structural-sharing lists/maps so a "modified copy" is O(log n), not a full copy — the Immutable.js / Clojure lane. It would also relieve the pressure the residency system was built to absorb.

Value · mediumEffort · high
A true hash map for stzHashList

Real key semantics — case-preserving, arbitrary key types — instead of the current lowercase-folding associative list. Lifts the specialized-collections lane toward Python dict / Immutable.js Map.

Value · mediumEffort · medium
Lazy / streaming pipeline

A lazy iterator that fuses map/filter/take without materialising intermediates — the one thing Rust iterators and Lodash chains do that the engine-expr pipeline does not yet.

Value · mediumEffort · medium
