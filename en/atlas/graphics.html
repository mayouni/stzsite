Graphics

One Zig engine across twelve lanes, text, colour, cartography, GPU, under one governed system.

6 Strong 3 Solid 2 Partial 1 Emerging

Measured against: Skia · D3 · Graphviz · Folders: base/graphics(opens in a new tab) · For programmers: this area's reference

Graphics in Softanza is the drawing of text, colours, shapes, charts, maps and diagrams. It is not a new engine: it is the GPU layer that the library already owned for calculation, extended to draw as well as compute. The GPU is the graphics card. Other tools ship one drawing lane done well; this plane runs twelve lanes under one governed system of colour and text.

Text came first, with Arabic as the acceptance test. The text pipeline reorders mixed-direction text with SheenBidi, shapes letters with HarfBuzz (choosing the glyph, the drawn form of a letter, that fits its position), justifies Arabic with kashida (a stretch of the line that joins letters) at the points the font declares, falls back from one font to another, and sets vertical CJK (Chinese, Japanese and Korean). The Arabic spelling of Softanza is shaped into one right-to-left run of eight glyphs. Placed between Latin words, the text splits into three runs. A test checks this. Colour is OKLCH throughout, a colour model in which equal steps look equally different. Ramps (series of colours) get evenly lighter by construction, every fill comes with a colour that can be read on it, and legibility is checked as a number, and the check can fail: a mid-grey on white is refused. The example below checks the legibility of the grey #999999 on white, which gives false, then of the dark grey #333333 on white, which gives true.

# legibility is a number that can say no
? StzIsLegible("#999999", :White)
#--> FALSE

? StzIsLegible("#333333", :White)
#--> TRUE

One canvas can produce SVG, a vector picture format, with no GPU at all. With a device, it renders a lossless PNG, supersampled (computed at a higher resolution and then reduced). The vector picture and the pixel picture cannot disagree, because one layout serves both. Computing and drawing share the device, so a simulation sends its data to its picture without copies: in one test, 16 bytes per frame crossed to the card instead of 1.7 MB. The plane also has 44 map projections, spatial statistics, 25 diagram notations, an accessibility tree (a description of the interface that screen readers use), and a first step toward image reading: a round trip that draws text and reads it back with OCR (text recognition). The example below creates a canvas of 300 by 120 pixels with a white background and adds a rectangle and a circle. It reports two shapes and checks that the SVG output exists.

o1 = new stzCanvas(300, 120)
o1 {
    SetBackground("white")
    AddRect(10, 10, 120, 100)
    AddCircle(220, 60, 40)
}

# two shapes on the display list
? o1.ShapeCount()
#--> 2

# the same picture, as SVG: vector, with no device
? StzFindFirst("<svg", o1.ToSVG()) > 0
#--> TRUE

Softanza graphics does not replace Skia (a 2D drawing library) or D3 (a chart library) in their own lanes, and the Compass says where. There are no general paths or Bézier curves, no transform stack, only linear gradients, no CPU rasteriser (drawing without a GPU), half of the chart family is missing, and there is no animation. Six lanes (sub-areas) are rated Strong and three Solid. The advantage of this plane is that its lanes work together, and the gaps that matter are those a user expects a lane to have. Use Skia or D3 when you need those features.

Where it stands

The Softanza Compass's reading: every lane of the area rated against the best of its category, by what the guards prove. Read from the source on 2026-09-15. The Compass's sentences are in English, as it wrote them.

Most of the field ships one lane well: Skia renders, D3 charts the web, Graphviz lays out graphs, spatstat does the statistics and draws nothing. Softanza is one Zig engine behind declarative Haro faces that reaches across twelve of those lanes at once — and the honest read below says which are genuinely strong, which are solid, and which are still gaps worth closing.

The one-sentence position. Softanza's advantage is not being best-in-lane against Skia or D3 — it is being coherent across twelve lanes under one governed colour and text system, which no single competitor is. The gaps that matter are where a lane a user expects (charts, curves) falls short of that coherence; the gaps that don't are the ones we chose (data services, a second GPU, vendoring the world).

Rethought from first principles

What Softanza kept from what works, and what it rethought, as the library wrote it down in its design documents and narrations.

The Softanza wayGraphics is not a new engine: it is the GPU layer Softanza already owns, taught to draw as well as compute.

Kept from the best practice

  • Text shaping is delegated to HarfBuzz and bidirectional order to SheenBidi. Correct Arabic shaping is a specialty built over many years, not something to rewrite. source(opens in a new tab)
  • Windows on all three desktop systems come from GLFW, a small proven library, instead of three hand-written windowing layers. source(opens in a new tab)
  • The colour system keeps proven ideas. Each shade step names its job (surface, border, text), and every fill comes with a paired colour readable on it. source(opens in a new tab)

Rethought

  • Computing and drawing share one GPU device, so a simulation feeds the picture without copies. In one test, 16 bytes per frame went to the card instead of 1.7 MB. source(opens in a new tab)
  • Unicode text is required from day one, with Arabic as the acceptance test. One layout serves every output, so the vector and pixel pictures cannot disagree. source(opens in a new tab)
  • Every drawing can always become SVG with no GPU, so pictures can be produced and checked anywhere. Without a device, a PNG request is refused and counted. source(opens in a new tab)
  • Colour ramps are computed in OKLCH, so each step is evenly lighter and never out of order. Contrast becomes a number that can make a theme fail. source(opens in a new tab)

12 lanes, each against the best of its category

For every lane: what runs in the engine today, the tools it is fair to measure it against, and what is still owed.

01Text & typographyStrong

In the engine

A full Unicode pipeline — SheenBidi → HarfBuzz → stb_truetype: bidi reorder, OpenType shaping, Arabic kashida justification at font-declared points, fallback chains, vertical CJK, glyph-id witnessing.

Measured against

HarfBuzz + FreeType + ICUBrowser text enginesPango

To complete

Line breaking / multi-line paragraph layout; an IME-grade retained layout; text halos as a first-class primitive.

02Colour systemStrong

In the engine

OKLCH/Oklab throughout, monotonic ramps by construction, a five-value semantic family governed by a constitution, ten themes, and WCAG 2 + APCA contrast as gate-able numbers (StzIsLegible, StzContrastLc).

Measured against

D3-colorchroma.js / culoriAdobe Leonardo

To complete

Colour-blindness (CVD) simulation — deuteran / protan / tritan — and a "safe under CVD" check beside the contrast one.

03Cartography & projectionsStrong

In the engine

44 projections with inverses (analytic + a shared Newton/Jacobian solver), WGS84 geodesy with ECEF/ENU frames and DMS, GeoJSON/TopoJSON, choropleth · symbol · flow · hex-bin, insets, Tissot, scale bar, north arrow, day-night terminator.

Measured against

D3-geoWolfram GeoGraphicsCartopyGeoTools

To complete

Not the projection count (nobody's analysis is wrong for want of Wagner VII) — it's live interactivity, which is the GUI plane's to add on GE5's hands.

04Spatial statisticsStrong

In the engine

Clark-Evans with its z-test, Ripley's K/L, G & F functions, simulation envelopes, mean centre / Weiszfeld median / SD ellipse; kernel density, marching-squares contours; IDW, fitted variograms and ordinary kriging with its variance surface; seven point-process null models.

Measured against

spatstat (R)PySALArcGIS

To complete

Broadly at parity for the analyst's core questions — the rare lane where a general graphics library also computes the statistics it draws.

05DiagrammingStrong

In the engine

25+ notations, all closed (DN0–DN24): flowcharts, DRAKON, BPMN, UML, org, Gantt, ER, Petri nets, fault trees, fishbone, network, floor plans — many constraint-solved, not placed. Own deterministic layout engine (GG1–GG6) plus a live "picture-as-input" mode.

Measured against

GraphvizMermaidPlantUMLD2

To complete

Force / hierarchical graph layout still shells out to dot.exe — the one external-binary runtime dependency.

06GPU compute + renderStrong

In the engine

In-house wgpu (WebGPU) surface: instanced multi-texture render and compute — matmul, fft, softmax, topk, pairdist — composed zero-copy on one device, with a W-string → WGSL transpiler.

Measured against

raw wgpu / Dawnthree.jstaichiregl

To complete

Single-GPU discipline is a deliberate constraint, not a gap; browser (WebGPU) tier is proven, the multi-device story is out of scope by choice.

072D vector renderingSolid

In the engine

Retained display-list canvas with an SVG floor that always answers, GPU-backed PNG (lossless, auto indexed/RGB/RGBA) and supersampled hi-res. Rect, rounded-rect, circle, ellipse, line, polyline, polygon, mesh, tinted image; linear gradient; rect clip; SVG hit-testing.

Measured against

SkiaCairoHTML Canvas / SVGPlutoVG

To complete

No Bézier / arc / general AddPath, no affine transform stack, only linear gradients — and the CPU rasteriser was never written, so PNG needs a GPU device or refuses to the SVG floor.

08AccessibilitySolid

In the engine

An accessibility tree with roles, names, reading order and ToJSON, a screen-reader bridge, and the contrast/legibility maths already gating colour choices.

Measured against

axe-coreBrowser a11y treeWAI-ARIA

To complete

CVD simulation (shared with colour); an a11y layer for raster canvas / geo / diagram output beyond the GUI document tree.

09Output & portabilitySolid

In the engine

SVG everywhere (no device needed), lossless PNG with a returned encode decision, raw pixel buffers, native window and browser tiers. Engine, SVG and PNG are cross-platform by construction.

Measured against

Cairo (PDF/PS)Skialibrsvg

To complete

No PDF, JPEG or WebP export; only Windows is runtime-verified — Linux/macOS windowing is vendored but not yet run on hardware.

10Charts & data-vizPartial

In the engine

Bar, horizontal-bar, multi-bar, line, scatter, histogram, surface and treemap — each with SVG and PNG backends and a terminal renderer, over a real stats plane (stzDataSet, hypothesis tests).

Measured against

D3Vega-LitematplotlibEChartsObservable Plot

To complete

The most crowded field, and the weakest lane: no pie/donut, area, heatmap, box/violin or candlestick. Closing these is the highest-visibility win.

11Interactivity & animationPartial

In the engine

Canvas hit-testing (Pick), SVG ids/classes for hover, a GUI event model that surfaces the input source and counts dropped events, and a drag-driven live diagram.

Measured against

D3 transitionsGSAPFramer Motion

To complete

Animation, transitions and tweening are explicitly deferred — no timeline / easing API yet. GUI-plane (G5) territory.

12Perception — the plane can draw, not yet seeEmerging

In the engine

The VISION plane's first rung: a draw→read round trip proven through Windows.Media.Ocr and onnxruntime (10 ms, glyph-accurate incl. Arabic shaping quirks) — perception, not just production.

Measured against

OpenCVTesseractCloud Vision

To complete

Nearly all of it — image recognition, classification, document understanding. The largest new direction, and a deliberate frontier.

What is owed, in the order of return

The gaps, ordered by what they bring and not by their size; value is the effect on the library's reach, effort an engineer's reading.

Tier A — foundational, unblocks several lanes

General paths, curves & transforms

Bézier / arc / AddPath and an affine transform stack. Flat art, maps and diagrams all work today — but smooth chart lines, rounded flows and rotated groups all wait on this one primitive. It is the single most-reused missing piece.

Value · highEffort · medium
Complete the chart family

Pie/donut, area, heatmap, box/violin, candlestick — engine renderers plus stzPlotCanvas faces. This closes the weakest lane against the most crowded field, and it is the most visible "we do that too" win.

Value · highEffort · medium

Tier B — cheap and high-leverage

Colour-blindness simulation

Deuteran / protan / tritan transforms and an IsSafeUnderCVD check beside StzIsLegible. A small addition to an already-strong colour system that competitors treat as a headline feature.

Value · highEffort · low
Radial & conic gradients + halos

Two more gradient kinds and a first-class text halo (hand-rolled today). Small, and they lift the quality of every figure the plane already draws.

Value · mediumEffort · low
Multi-line paragraph text

Line breaking over the existing pure-function layout — a wrapper, not a rewrite. Unlocks captions, annotations and any label longer than a line.

Value · mediumEffort · medium

Tier C — strategic, larger

Animation & transitions

A timeline / easing / tween API — the deferred lane. Belongs with the GUI plane's reactive layer (G5) rather than the canvas.

Value · mediumEffort · high
PDF export & the raster floor

An SVG→PDF path for print/publication, and either the never-written CPU rasteriser or an accepted device-free raster route so PNG no longer needs a GPU.

Value · mediumEffort · high
Own graph layout · cross-platform proof · perception

Retire the dot.exe dependency; run and CI-verify Linux/macOS on real hardware; and mature the VISION plane from OCR to recognition. Each is a program, not a patch.

Value · strategicEffort · high
