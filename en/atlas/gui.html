GUI & reactive

A young RmlUi plane with standout right-to-left and accessibility; the reactive runtime is not yet wired to the view.

2 S6 So4 P

Measured against: Qt · GTK · Flutter · React · Folders: base/gui · base/reactive · base/app · The original Atlas page

A young but genuinely coherent GUI plane, built on vendored RmlUi and actually running — windows open, events flow, it renders through the GPU plane and an SVG tier. Two standouts reflect the library's DNA: RTL/bidi fully owned and accessibility built in from the grammar up. The rest is early: a four-primitive vocabulary, flexbox-only layout, imperative view-binding, and a full reactive runtime that ships but is not yet wired to the GUI. The whole plane is on local main only, not yet pushed.

What stands out

  • RTL/bidi fully owned end to end
  • accessibility mandatory at authoring time, exposed via AccessKit
  • a recorder-not-painter render model with a deviceless SVG tier
  • an event surface that counts dropped events

What is owed

  • wire the reactive runtime to the GUI (G5 clause 2)
  • a richer widget set
  • the semantic theme system (G6)
  • IME & two-way text editing

The lanes, one by one

RTL & bidirectional text
Strong
Fully owned (RmlUi does no bidi): stzUiDocument reverses flex rows under RTL; gpu_text.zig reorders with SheenBidi (UAX#9) and shapes Arabic with HarfBuzzstzUiDocument / gpu_text.zig; test/gui RTL suite
Accessibility
Strong
G4a: a mandatory RATIONALE on every element emits an ARIA-role tree; G4b: a11y.zig hands that tree to AccessKit (UIA / NSAccessibility / AT-SPI)stzAccessibilityTree / a11y.zig
Declarative authoring (.panel)
Solid
A closed four-kind grammar PANEL/BOX/TEXT/STYLE, a diagnostics court, a .panel->RML->.panel round-trip fixpoint; far narrower than peer component modelsstzUiDocument
Layout
Solid
RmlUi flexbox via RCSS: direction, wrap, gap, align, justify, px/%/fill sizing; CSS Grid refused by decision, no constraint or custom layoutstzUiDocument.ring::ToRml()
Rendering backend
Solid
RmlUi's render interface is a recorder, not a painter (stz_rmlui.cpp): one flat display list drawn by the GPU tier or an SVG tier; PNG needs a GPU devicestz_rmlui.cpp
Event handling
Solid
Pointer, key, text-input, focus and directional focus move, hit-testing (element_at), an event recorder that counts dropped events; no gesture recognitionstzPanel
Reactive runtime & signals
Solid
stzReactiveObject with Watch / Computed(deps) / BindTo / SetAttribute, streams, timers, HTTP, event bus on a libuv reactor; not yet reaching the viewbase/reactive; reactor.zig
App shell & windowing
Solid
Native windows via vendored GLFW (window.zig); stzApp is a declarative living world; no multi-window orchestration, dialogs, menus or system-traywindow.zig / stzApp
Widget / element toolkit
Partial
RmlUi's own form controls (input, select, textarea, progress, tabset, button); no tables, trees, menus, dialogs, pickers, toolbars, docking
State->view binding
Partial
{placeholder} templates and Set/SetStyle/Apply mutate a live document preserving focus, values escaped as data; imperative, not reactivestzUiBindings (G5 clause 1)
Text input & IME
Partial
Single-line text input works (stz_gui_text_input); no IME, composition input for CJK and complex scripts deferred (costed at 1-3 engineer-years)
Theming & animation
Partial
Inline styling (BACKGROUND, COLOR, STYLE bags -> RCSS) and a profile layer; no semantic theme system (G6 not started) and no animation/transitions
