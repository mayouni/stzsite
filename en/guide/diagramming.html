  • SetNodeLabel A node could only ever be labelled at birth, via AddNodeXT(id, label); there was no way to say it afterwards, and no way to ask. So a format that reads a node first and learns its label a line later (.stzsim's `add node X` / `label: "..."`) had nowhere to put it. in stzGraph
  • SetLayout A LAYOUT NAME THIS DOES NOT KNOW IS REFUSED, not stored. It used to take anything, and an unrecognised name became top-down in silence -- so `SetLayout(:LeftToRight)` drew a top-down picture and there was nothing anywhere to say the instruction had been dropped. A setter that accepts a value it will not honour is worse than one that refuses: the caller has evidence of neither. in stzDiagram
  • SetNotation THE NOTATION (DN0) ------------------------------------------------ Takes a registered name or a profile object. A name the registry does not know resolves to the default -- a diagram always has a notation, the way it always has a theme. in stzDiagram
  • SetFocusColor The focus colour's setter, missing until now. ExportToStyl() has always WRITTEN a focus section (color + penwidth), and _ApplyStyle() has always called This.SetFocusColor() to read it back -- a method nobody had written, so loading any exported .stzstyl died on R14. Same shape as its siblings: resolve the name, keep the resolved value. in stzDiagram
