Performance

Performance is something a program knows about itself: the engine measures, the code declares the budget, and any corrective act passes through governance.

The functions, by what they do

Testing and checking

  • Check Judging -------------------------------------------------- One judgment pass. Fires alerts on TRANSITIONS only: a rule breaching now that was fine before -> breach alert; a rule fine now that was breached before -> clear alert. Returns the number of NEW breaches this pass. in stzPerfSentinel
  • CheckAgainst Judging -------------------------------------------------- Judge every expectation against the monitor's MEASURED numbers. Returns the breaches as findings in the unified rule shape ([ :rule, :subject, :where, :severity, :message ], subject "perf") -- hand them to stzRuleReport.Ingest(). Full verdicts (passes included, with actuals) stay readable via Verdicts(). in stzSla

Counting and measuring

  • Count Samples ever recorded on this metric. in stzMetric
  • MeanMs Lifetime mean -- exact (engine keeps the true sum; the buckets quantize, the sum does not). in stzMetric
  • MaxThroughput Where this machine saturates IF CPU is the constraint (req/s). in stzPerfProfile
  • Size Samples retained in the window (never exceeds Capacity()). in stzPerfSeries

Replacing and setting

  • Set Gauge face in stzMetric
  • SetChannels The event-bus channels alerts fan out on (process-global). in stzPerfSentinel
  • SetBusyMs configuration in stzLoadDriver

Converting

  • ToOtelJson One OTLP-style span as a JSON string. in stzStopwatch
  • ToOtelSpan OpenTelemetry export (industry interop) ------------------ The span as a hashlist in OTel vocabulary. Absolute anchors in unix NANOS as STRINGS (integer ms + "000000" -- exact, since f64 cannot hold epoch nanos); exact ns duration as an attribute. in stzStopwatch
  • AsWarning Soften the LAST closed expectation: it advises, it does not fail the gate (stzRuleReport.IsSound ignores warnings by convention). in stzSla
  • ToJson The OTLP resourceSpans envelope, every collected span inside. in stzOtelBatch

Reading and writing

  • LoadRatio The demand signal for elastic scaling (perf P6): how close this workload is to its CPU ceiling, X/Xmax in 0..1. This is what stzClusterSupervisor.ReportLoad() always wanted -- MEASURED, not hand-fed: FeedLoadFrom(tag, oProfile) closes the loop. 0 when nothing is measurable yet (no requests / no demand). (Named LoadRatio: `load` is a Haro keyword.) in stzPerfProfile

Walking and applying

  • RunFor Standalone continuous mode: drive the cadence for nMs (blocking; for scripts and guards -- servers should host, not block). in stzPerfMonitor
  • ExecuteOn The crossing (admission is governed) --------------------- Apply the plan to the target -- a stzAppCluster, or any object answering ScaleUp(tag)/ScaleDown(tag)/RestartDead() (a double in rehearsal, per the service-virtualization pattern). Returns the number of actions committed; 0 with a full refusal audit when the actor may not commit. in stzPerfPlan
