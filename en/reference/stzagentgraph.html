stzAgentGraph

25 own methods · 10 forms written with extensions, listed under their method

the source: base/agentic/stzAgentGraph.ring(opens in a new tab) · All classes · The area reference: Agents & conversation

The composition of an agent system as a graph that can be judged: who proposes, who guards, what has an effect on the world, where the trace goes, and the proof that no effect is reachable without passing a gate.

Nodes are declared by kind, a language-model actor, a guardian, an effect, a trace sink, and edges by meaning, proposes, guards, traces. A model actor starts with an empty set of capabilities and its output is marked as open text.

oAG = new stzAgentGraph("mailer-bad")
oAG {
    AddLLMActor("writer")
    AddEffect("send")

    Proposes("writer", "send")
}

# a model proposing straight to an effect
? oAG.IsSound()
#--> FALSE

# which invariant is broken, and on which node
? oAG.Violations()[1][:invariant]
#--> effects-guarded

? oAG.Violations()[1][:node]
#--> send
run in the library on 2026-10-20

The verdict is not an opinion: the violation names which invariant was broken, and on which node. Add a guardian before the effect and a witness after it, and the same system is sound.

oAG = new stzAgentGraph("mailer")
oAG {
    AddLLMActor("writer")
    AddGuardian("gate")
    AddEffect("send")
    AddTraceSink("audit")

    Proposes("writer", "gate")
    Guards("gate", "send")
    Traces("send", "audit")
}

# the same system, with a gate before the effect and a witness after it
? oAG.IsSound()
#--> TRUE
run in the library on 2026-10-20

Capabilities are granted through a governed door that refuses what no door allows, and any node whose properties no longer match the sealed record is reported as tampered with. The same invariants exist as a declared rule set and as findings in the library's unified shape, so a CI report collects them beside every other rule. It serves whoever builds with language models and must show, before the first message is sent, that nothing effectful happens without a deterministic gate in front of it.

MayGrant
Violations() below is the AUDIT -- it catches a bad graph after it is built. Grant() is the GATE: the governed way to add a capability, which REFUSES granting 'effectful' to an llm actor at the moment of expression, so the no-llm-effectful violation can never enter the graph through the sanctioned door. (A raw SetNodeProperty still bypasses it -- the audit stays the backstop -- but the composition API refuses.) This is the guardrail moving from audit to gate.
