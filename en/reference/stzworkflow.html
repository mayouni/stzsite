stzWorkflow

46 own methods · 7 forms written with extensions, listed under their method · Also inherits from stzDiagram (245) · stzGraph (291)

the source: base/graph/stzWorkflow.ring(opens in a new tab) · All classes · The area reference: Diagramming & graphs

stzWorkflow is a class that describes a process as a diagram and records which kind of process it is. A process is either a sequence of steps or a state machine. A state machine is made of states and of transitions between them, and each transition is caused by an event. The class also holds the actors who do the work and keeps the exceptional path apart from the intended one.

You need it when a team wants one definition of a process, such as an approval chain, an order's life, a support escalation or a protocol, that it can read, test and print.

You choose the kind first, then declare the process in its vocabulary. For a sequence, you add steps connected one after the other. For a state machine, you add states and the transitions between them, each named by the event that causes it. The example below declares an order with three states, new, paid and shipped, and two transitions. It checks that the workflow is a state machine and that it has three nodes.

o1 = new stzWorkflow("order")
o1 {
    SetWorkflowType(:StateMachine)

    AddState("new")
    AddState("paid")
    AddState("shipped")

    AddTransition("new", "paid", "pay")
    AddTransition("paid", "shipped", "ship")
}

? o1.IsStateMachine()
#--> TRUE

? o1.NumberOfNodes()
#--> 3
run in the library on 2026-10-20

You can assign actors, the people or roles who do the work, to the process. You can mark some transitions as unwelcome, which means exceptions. A layout can then keep the intended path straight and push the exceptions aside. This is a BPMN rule that makes such diagrams readable, and BPMN is a standard notation for drawing business processes.

A workflow is a diagram, so it inherits what stzDiagram and stzGraph do: reachability (which nodes can be reached from which), cycles, the shortest route through the process, themes, notation, and rendering to SVG or PNG. A workflow is therefore both a checked thing and a drawn thing.

Use it for a process that you want to define once and use both for checking and for drawing. For a diagram that is not a process, see stzDiagram.
