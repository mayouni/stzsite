stzRuleReport

16 own methods · 0 forms written with extensions, listed under their method

the source: base/graph/stzRuleReport.ring(opens in a new tab) · All classes · The area reference: Diagramming & graphs

One gate for every rule of the library: each graph checks itself and hands its findings to a single report, in a single shape, whatever domain they came from.

oOrg = new stzOrgChart("acme")
oOrg {
    AddExecutivePosition("ceo")
    AddStaffPosition("rogue")
    ReportsTo("rogue", "rogue")
}

oRep = new stzRuleReport("acme")
oRep.Collect(oOrg)

? oRep.NumberOfFindings() >= 1
#--> TRUE

# which graph produced them
? @@( oRep.Subjects() )
#--> [ "orgchart" ]

# and whether the whole is sound
? oRep.IsSound()
#--> FALSE
run in the library on 2026-10-21

A finding says which rule, about which subject, where, how severe and in what words. The report collects them from code rules, agent graphs, security reachability, organisation charts, service registries and diagram models; it counts the errors and the warnings, names the subjects that produced any, and says whether the whole is sound. Older checkers whose findings had other shapes are ingested under a subject and normalised.

Each graph owns its rules and the report only reads them, which is what lets one gate in the build judge eleven domains. It serves the build that must fail on a security hole and on an organisation chart with a loop alike.
