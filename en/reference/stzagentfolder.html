Rescan
AND ONE THING IT CANNOT DO, REPORTED RATHER THAN HIDDEN: a changed .pia file is re-read, because it is data. A changed .ring file is NOT re-evaluated, because Haro cannot unload a function and re-loading it is a C22 redefinition that takes the library down. So the old code keeps running and this rescan says so, as a refusal carrying the file's name. A reload that quietly kept stale code would be the worst of the three available outcomes.
MountOn
Declare() is called for each even though a declared agent answers CoverageStatement() and ReversibilityClass() for itself: a Haro agent may answer only one of them, and the host's declared table is the fallback the engine gate reads. Saying it twice costs nothing; saying it never is a refusal at RunFor() time.
