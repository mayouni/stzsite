StopLoop
F5: the reactor is deliberately NOT destroyed here. The manager/http hold handle-sharing COPIES (Haro attribute assignment copies objects), so destroying from Stop() -- which timer callbacks may invoke MID-LOOP -- would leave those copies submitting on a freed loop (use-after-free). The idle loop thread is reclaimed at process exit; callers needing eager teardown may ReactorQ().Destroy() once no loop is running.

StopTimer
The object branch used to be just _timer_.Stop(), which set a flag on whatever the caller was holding. The manager stores a COPY, so the copy it is running never heard about it and went on firing. Removing it from the manager BY ID is what actually stops a timer -- proven: the id path takes the registration from one to zero.
