stzProcess

35 own methods · 2 forms written with extensions, listed under their method

the source: base/system/stzProcess.ring(opens in a new tab) · All classes · The area reference: System programming

A child process held in the hand: started, read as it speaks, waited for, killed, and never left behind, since closing the handle of a running child kills it first.

Starting it is an effectful act, the kind that a virtual system rehearses before it is allowed to happen. The output is read as a stream, which blocks until at least one byte arrives and answers an empty string at the end, or all at once to the end; the error stream is read the same way. Waiting answers the exit code and may be done twice, and success or failure can be asked for, or the child ended at once.

The object also knows its own process: its id, and its uptime on the monotonic clock in seconds, milliseconds or nanoseconds. The difference from stzSystemCall is the difference between a conversation and a command: a system call runs to completion and returns three channels, a process is held open and talked to while it runs.

It serves a long-running tool read line by line, a server that a test starts and stops, a worker that the program supervises, and anything where "wait for it to finish" is not the whole story.
