stzAppServer

61 own methods · 7 forms written with extensions, listed under their method

the source: base/appserver/stzAppServer.ring(opens in a new tab) · All classes · The area reference: Web & app server

A web server that is also a host: it answers HTTP, serves over TLS, exposes a database table as a REST resource in one call, mounts a sign-in router and an OpenID provider, listens to raw devices, and ticks a fleet of agents between requests, on the same loop, in the same process.

o1 = new stzAppServer()

# port 0 asks the system for a free one
o1.Start(0, "127.0.0.1")
? o1.IsRunning()
#--> TRUE

o1.Stop()
? o1.IsRunning()
#--> FALSE
run in the library on 2026-10-19

It never half-starts: binding a port either succeeds or raises. Routing has the familiar shape, get, post, put and delete, with path parameters and wildcards, an exact route winning over a parametric one, middleware and static files; an unknown path is an honest 404.

Security is mounted, not bolted on. A whole sign-in surface sits at a prefix, with secure cookies whenever the listener is TLS; the server's own login can become the login of other applications; off-loopback requests can be required to be signed, with a replay ledger; and the reason the last request was refused can be asked for in words. Every request's response time is recorded under the perf system's well-known subject. Agents live here too, supervised, and retired only when their declared obligations are fulfilled.
