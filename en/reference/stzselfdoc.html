stzSelfDoc

16 own methods · 0 forms written with extensions, listed under their method

the source: base/meta/stzSelfDoc.ring(opens in a new tab) · All classes · The area reference: Metaprogramming & code rules

A class that can be asked about itself: what methods it has, which ancestor defines each, what the source says about one, and, in words, which method does what you mean.

oDoc = StzSelfDocQ("stzList")

# asked in words, it composes the name
? StzFindFirst("RemoveDuplicates", oDoc.HowTo("remove duplicates")) > 0
#--> TRUE

# and answers whether a name exists
? oDoc.HasMethod("DuplicatesRemoved")
#--> TRUE

? oDoc.HasMethod("Duplicatez")
#--> FALSE
run in the library on 2026-10-21

The knowledge is already in the source, so no language model is involved. A request in words is composed into a method name by the naming grammar of the library, and the answer says that it was composed and not found; asking for a method that does not exist is refused instead of being invented. A method can be explained from the comment above it, a class can be asked a question, and the best method for an intent can be chosen.

This is the self-documentation from which the reference of this site is harvested, and against which the how-to recipes were checked. It serves a programmer who does not know the name, and an agent that must not guess one.

HowTo(intent) -- resolve a plain-English intent to a runnable method call on this class, DETERMINISTICALLY (no LLM). Two engines, unified: (1) the GRAMMAR composes a method name from the intent and grounds it against this class's real API; if the class implements it, that is the answer (highest confidence, it is derived not guessed).
